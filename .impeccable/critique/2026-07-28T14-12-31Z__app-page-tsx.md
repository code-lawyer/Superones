# Design Specificity Verdict

**视觉上是为 Vault2077 创作的，产品旅程上仍不够专属。**

当前的暖灰档案纸、零圆角登记表面、中文衬线与无衬线分工、编号元数据和整行反色，完整延续了“公共档案仪器”。它没有退回通用圆角 SaaS 卡片。

但主体构图仍可套用在许多科技媒体首页：大字标、新闻主栏、项目榜单和服务面板。Vault2077 独有的四轴系统——情报、经营、进化、公开建造——只被写在文案和导航标签里，没有转化为访客能立即理解并行动的选择模型。

自动检测器对 `app/page.tsx` 返回 `[]`，共 0 条规则命中、0 个误报。这说明常见结构反模式并不是问题来源。浏览器证据补充发现：实时页面会在更新时间缺失时显示“更新 更新中 CST · 128 个来源”；微型元数据过小；左侧内容面板存在明显的无效纵向留白。可变脚本注入在浏览器只读环境中失败，因此没有可靠的用户可见 `[Human]` 覆盖层。

# Overall Impression

这是一个已经建立视觉权威、但尚未建立首页决策权威的方案。最大机会不是换颜色、换字体或加动效，而是把“四频道坐标系统”变成首屏真实可用的信息架构，让用户先知道该去哪，再看系统今天收录了什么。

# What’s Working

- “公共档案仪器”的材料语言执行得很稳定：纸张色阶、连接细线、方正边界与稀缺反色共同建立了制度感。
- 页面使用真实时间、来源数、事件判断、GitHub 平台原生排名和赛季时间作为证据，没有用虚构客户评价或营销数字填充首页。
- 三条预览的分组方式清楚，整行链接有较大的命中区域，悬停与键盘聚焦都能通过反色和短距离位移给出反馈。

# Priority Issues

## [P1] 四频道首页没有表现为四频道网关

**为什么重要：** `home-waterfall` 把 Feed 设为 1.62fr 主栏，右侧 SiC 与 OPC 又共同撑高整个网格，结果是 Feed 留下大面积空纸，OPC 只露出一部分，Frontier 完全离开截图。用户会自然推断“这是信息门户，其他频道只是附加功能”，与全站规格直接冲突。

**修复：** 首屏先放一组紧凑的四入口登记栏或 2×2 坐标面板，每个入口都用任务动词、结果说明和一条真实状态帮助决策；内容预览移动到下一层。不要再让内容量不同的两列共享同一个拉伸高度。

**Suggested command:** `$impeccable shape`

## [P1] OPC 首页承诺混淆了 Vault 交付与外部顾问责任

**为什么重要：** `FIXED SCOPE / FIXED PRICE` 位于整个 OPC 面板之上，而面板内同时包含“游骑兵协会”。这会让高风险经营服务的用户误以为独立顾问同样由 Vault2077 定价、收款和担责。

**修复：** 将入口明确拆成“Vault2077 标准服务”和“外部独立顾问”，或者移除覆盖全栏的固定价格眉题，并在游骑兵入口旁直接显示“独立联系 / 独立定价 / 独立交付”。

**Suggested command:** `$impeccable clarify`

## [P2] Masthead 只命名系统，没有教用户进入系统

**为什么重要：** “从信息、经营、进化到公开建造”说明了范围，却没有回答忙碌的一人公司此刻应从哪里开始。“前方高能！”是通用的互联网情绪词，也削弱了品牌的准确和可核验气质。

**修复：** 改成一条产品主张与四个任务动词组成的方向层。例如把入口组织为“核验变化 / 建立经营结构 / 跟进能力 / 公开建设”，频道名作为第二层术语。最终主张文案需由产品方确认，不在设计阶段虚构新效果承诺。

**Suggested command:** `$impeccable clarify`

## [P2] 微型元数据与重复动作降低理解效率

**为什么重要：** 8–9px 的元数据在宽屏截图里已经接近不可读；`OPC`、`SiC`、重复的“查看全部”和未标记的新标签外链都增加了翻译成本。

**修复：** 首页元数据至少提升到 caption/note 层级；把“查看全部”改为“进入信息流 / 浏览学院 / 查看服务目录”等具体动作；外链增加文本或图形标记，并在可访问名称中说明会打开新窗口。

**Suggested command:** `$impeccable typeset`

# Cognitive Load

当前为 **中等认知负荷，8 项中失败 3 项**：

- **单一焦点失败：** 同一屏同时要求理解平台、选择四频道、点击多条记录或“查看全部”。
- **视觉层级失败：** Feed 与 SiC 占据主要注意力，OPC 被截断，Frontier 不可见。
- **最少选择失败：** 顶部四个频道、多个“查看全部”和六条可见记录同时出现，超过单个决策点适合处理的数量。

分组、三项一组的 chunking、工作记忆支持和基础渐进披露表现良好。

# Emotional Journey

- **到达：** 大字标与制度化网格带来权威感。
- **定向：** “坐标系统”有吸引力，但用户必须自行把频道名称翻译成任务，体验快速下坠。
- **证据峰值：** 真实更新时间、来源数、榜单和赛季数据使产品显得活着且可信。
- **情绪低谷：** 被撑高的空白 Feed 面板像内容未完成，不像有意留白；OPC 与 Frontier 又被压到更深位置。
- **结束：** 深色 Frontier 行动带本可以形成强峰值，但到达成本过高。
- **高风险安抚：** OPC 的责任边界是最薄弱的一点。

# Persona Red Flags

## Jordan（第一次访问）

- 五秒内无法判断应该点击顶部四格、某条事件还是“查看全部”。
- `OPC`、`SiC`、“超级个体”和“持续运行坐标系统”没有在选择点被解释。
- 新闻与榜单最显眼，可能导致他根本不知道经营服务和公开建设也是核心产品。

## Riley（边界测试者）

- 会立即发现 `FIXED SCOPE / FIXED PRICE` 与独立游骑兵责任边界的矛盾。
- 空状态与降级状态只有被动提示，没有重试和替代入口。
- `updatedAt` 缺失时会出现“更新 更新中”，证明回退状态没有经过真实语言验收。
- GitHub 项目会新开标签，但没有明确外链提示。

## Casey（移动端、注意力分散）

- 900px 以下主体顺序变成 Feed → SiC → OPC → Frontier，经营帮助与参与入口需要长距离滚动。
- 8–12px 元数据在手机和浏览器缩放下脆弱。
- 四频道紧凑入口只在顶部导航；如果移动导航折叠，正文里的频道又被拉得很远。

## Chen（已有收入的 AI 产品超级个体）

- 他带着“今天什么变了、我必须处理什么、下一步应该建设什么”进入首页，但首页提供的是四份库存，不是跨频道决策顺序。
- 新奇的新闻和 GitHub 项目占据注意力，高风险的经营结构却视觉次要。
- 他最需要来源与责任边界，OPC/游骑兵的总括性承诺恰好会损伤这一信任。

# Minor Observations

- 首页没有明确的全局导航活动状态，Wordmark 只能隐含当前位置。
- Header 与主体的频道顺序不一致。
- `.home-feed__item--lead` 已定义但未使用，Feed 三条记录缺少编辑层级。
- `prefers-reduced-motion` 没有覆盖 `institutional.css` 内的 `.home-content-item` 过渡。
- 页脚中的“ICP备案信息待接入”属于公开信任占位，不适合生产首页。
- `globals.css` 的 720px 移动导航规则加载在 `institutional.css` 的无条件 `.primary-nav` 之前，后者可能覆盖移动端 `display: none` 与移动行样式；应在真实 360/768 宽度验证并整理样式归属。

# Questions to Consider

- 如果 Vault2077 是一个坐标系统，为什么首页看起来像一个新闻产品加三个附录？
- 四个频道在任何内容预览出现前，是否都应该获得一次平等而清楚的可发现机会？
- “前方高能！”能否通过系统对每一条事实都采用的“证据先于装饰”标准？
- 如果移除所有频道名称，只保留用户任务，访客还能否一眼知道四个入口分别解决什么？
- OPC 的首页入口是否应该在第一眼就把“Vault 交付”和“独立顾问”分成两个责任主体？

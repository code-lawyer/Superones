# 公众 AI 应用合规上线

## 1. 产品卡

| 字段 | 内容 |
| --- | --- |
| 产品编号 | `OPC-ONCE-006` |
| 产品类型 | 基础设施 / 一次性交付 |
| 一句话结果 | 让一个直接调用已备案模型的公众文本生成应用完成适用性判断、属地登记材料、公示、标识、用户规则和上线检查 |
| 标准服务费 | 人民币 14,800 元，含税 |
| 标准内部周期 | 材料齐备后 10–18 个工作日；属地网信部门和平台等待时间另计 |
| 标准容量 | 一个主体、一个产品、一个主要版本、一条公众文本生成用户旅程、最多2个已备案模型、一个主要市场 |
| 现有目录关系 | 从 `I-07 数据、隐私与信息安全运行` 和 `S-06-03 数字产品上线合规包` 拆出的AI专用服务 |

## 2. 这个产品解决什么

本产品只处理一种可标准化路线：

> 中国大陆主体把已经备案的大模型能力通过API或云服务集成到一个面向境内公众的文本生成应用中，不训练、自研或微调基础模型。

产品最终建立以下链路：

```text
公众服务与算法属性判断
→ 已备案模型及供应商核验
→ 应用登记路径确认
→ AI数据流和第三方关系盘点
→ 模型公示与生成内容标识
→ 用户协议、隐私和投诉机制
→ 输入输出及人工复核基线
→ 上线测试与证据包
```

完全不提供AI功能、仅员工内部使用第三方AI办公工具、产品不向公众开放的创业者，不需要购买本产品。

## 3. 标准准入

### 3.1 必须同时满足

- 产品利用生成式AI向中国境内公众生成文本内容；
- 底层能力直接调用已公开备案的模型或服务；
- 最多使用2个模型，且模型名称、备案号、提供方和接口关系可核验；
- 不进行基础模型训练、继续预训练、微调、模型合并或自有权重部署；
- 产品不是医疗诊断、金融决策、新闻出版、教育考试等强监管核心业务；
- 主要用户不是未成年人，且不处理大规模敏感个人信息；
- 不包含直播、UGC平台、公开社区、社交传播或大规模个性化推荐；
- 用户可以安排开发者完成标识、日志、审核、投诉和界面整改；
- 没有已经发生的监管通报、重大安全事件或平台下架。

### 3.2 必须升级

- 自研、开源部署、微调或控制模型权重；
- 服务具有舆论属性或社会动员能力并触发安全评估和算法备案；
- 除生成合成外还提供个性化推送、排序精选、检索过滤或调度决策；
- 生成图片、音频、视频、数字人或深度合成内容，超出标准文本路线；
- 面向未成年人、患者、投资者或其他高风险群体；
- 使用用户数据训练、跨境传输输入输出或向境外团队开放日志；
- 多产品、多主体、多模型供应链或开放平台/插件生态；
- 已被投诉、通报、下架或要求开展专项安全评估。

### 3.3 不适用

- 只在企业内部使用办公AI、代码助手或内部知识库；
- 产品没有公众AI功能，只使用规则、搜索或普通自动化；
- 只需要模型选型、Prompt工程、产品开发或内容运营；
- 要求保证备案、登记、审核或应用商店必然通过；
- 要求隐瞒真实模型、功能、数据或用户范围。

### 3.4 重要边界

不使用“大模型”不等于一定没有算法备案问题。个性化推荐、信息流排序、检索过滤和平台调度也可能属于算法推荐服务；出现这些功能时应转算法专项判断。

调用已备案模型不需要把底层模型重复备案一次，但面向公众上线的应用仍需核验属地应用登记及模型名称、备案号公示要求。

## 4. 服务范围

### 4.1 包含

1. 一次公众服务、生成式AI、算法属性和安全评估适用性问卷；
2. 最多2个已备案模型的名称、备案号、提供方和接口关系核验；
3. 一个主要用户旅程的输入、模型调用、审核、输出、反馈和日志数据流；
4. 用户输入、输出、账号、日志、反馈和模型供应商数据处理检查；
5. 属地生成式AI应用登记路径核验、材料组织和一次标准补正；
6. 产品显著位置的模型名称、备案号和服务说明公示；
7. AI生成内容显式标识、文件或元数据隐式标识的适用性检查；
8. 一份AI服务用户规则、一份适配功能的隐私文本修订；
9. 投诉举报、人工复核、违法内容处置和重大事件升级SOP；
10. 禁止用途、用户提示、输入拒绝、输出阻断和模型降级规则；
11. 一套50个标准场景的上线前安全与产品行为抽样测试；
12. 最多15个主要页面/状态的AI合规检查；
13. 最终公众AI应用合规上线报告和证据包。

### 4.2 不包含

- 自研/微调模型备案、安全评估或完整算法备案；
- 模型训练数据审计、红队测试、正式安全评估或第三方检测；
- AI模型、审核、日志、标识、隐私或产品功能的开发整改；
- 图片、音频、视频、数字人及其他多模态内容的专门标识工程；
- 医疗、金融、新闻、出版、教育、未成年人等特殊行业意见；
- 等保备案、测评、渗透测试、数据出境或正式个人信息保护影响评估；
- 模型API、云服务、内容审核、短信、存储和其他持续费用；
- 已发生的投诉、处罚、下架、安全事件或争议处理；
- 持续内容审核、模型监控、月度复查或常年法律顾问。

## 8. 验收标准

- 产品确属直接调用已备案模型的公众文本生成标准路线；
- 模型名称、备案号、提供方和接口关系均可核验；
- 输入、输出、日志、审核、反馈和外部处理方无未知关键项；
- 应用登记有提交、回执、结果或明确外部等待状态；
- 产品显著位置正确公示模型名称、备案号和AI功能说明；
- 文本输出、复制和导出路径完成适用的AI生成标识；
- 用户协议、隐私政策、禁止用途和实际产品行为一致；
- 投诉、人工复核、违法内容处置和安全升级可以实际执行；
- 50个抽样场景执行完毕，严重缺陷清零，中低风险缺陷有责任人；
- 最终报告明确当前适用结论和所有复查触发条件。

主管部门登记或平台审核的最终结果不是无条件验收承诺。因Vault2077材料错漏产生的补正应免费处理。

## 10. 周期和暂停

- 属地网信部门、模型供应商、平台和应用商店时间属于外部等待；
- 用户未提供真实模型、架构、日志和功能时暂停；
- 需要开发整改时，从清单发出到新版本提交期间暂停；
- 产品新增模型、模态、推荐、UGC、分享传播或高风险行业功能时重新准入；
- 主管部门要求安全评估或算法备案时，标准链路暂停并升级。

## 11. 修改、变更与退款

- 包含两轮集中文本/界面修改和一轮因原事实产生的标准登记补正；
- 同一模型的小版本接口调整可作为修改；更换模型提供方、增加模型或改变主要功能属于变更；
- 新增图片、音频、视频、数字人或用户公开发布能力属于变更；
- 用户拒绝执行标识、投诉或内容处置等阻断性整改，可交付“未就绪报告”并按阶段结算；
- 因Vault2077错误判断标准路线而遗漏明确的算法备案要求，应退还未履行部分并完成材料交接。

建议阶段结算：准入20%、模型和数据核验35%、文件包60%、应用登记75%、整改复核90%、最终报告100%。准入比例高于其他产品，因为监管路径判断本身构成本产品的核心专业工作。

## 12. 异常升级

出现以下情况必须立即升级：

- 模型备案号、提供方或真实调用关系无法证明；
- 实际部署了自研、开源或微调权重；
- 产品存在公众舆论表达、社会动员、内容平台或大规模传播能力；
- 同时使用推荐、排序、检索过滤或调度决策；
- 训练使用用户输入，或日志被境外模型/团队持续访问；
- 涉及未成年人、医疗、金融、教育考试、新闻出版等高风险场景；
- 已出现违法内容扩散、重大投诉、监管问询或平台下架。

运营人员不得通过更改产品文案掩盖真实功能以维持标准准入。

## 13. 运营 SOP

1. 核验订单，发送AI产品、模型、数据、标识和安全问卷；
2. 由具备网信和产品能力的人员完成监管分流，至少一名复核人签字；
3. 从官方公开信息核验模型名称和备案号，不只接受供应商销售口径；
4. 冻结产品版本和主要用户旅程，记录版本号或构建标识；
5. 建立AI数据流、供应商、日志和内容处置映射；
6. 根据真实行为编写公示、协议、隐私和运营SOP；
7. 按属地路径准备应用登记材料并保存全部沟通和回执；
8. 开发者完成整改后，在真实测试环境核验标识、拒答、投诉和人工复核；
9. 执行50场景测试并分级缺陷，不以单次演示替代；
10. 第二人复核模型、登记、公示、测试和最终报告；
11. 交付证据包，撤销测试与后台临时权限；
12. 在维护日历中记录模型、功能、法规和供应商复查触发条件。

## 14. 测试与数据安全

- 测试集不得包含真实用户输入、生产个人信息或非法获取的敏感内容；
- 高风险测试使用最小必要、可控和可审计的样本，不制作或传播违法结果；
- 不保存模型API密钥、生产后台密码、短信验证码和签名私钥；
- 日志和输出截图必须清除令牌、手机号、身份证、客户信息和商业秘密；
- 临时测试账号、模型密钥和后台权限在服务完成后撤销或轮换。

## 15. 交付后复查触发条件

- 更换或增加模型、供应商、API、部署方式或模型版本；
- 从内部测试转为公众开放，或扩大用户/地区；
- 新增图片、音频、视频、数字人、UGC、分享、推荐或社交传播；
- 开始使用用户数据训练、精调或跨境处理；
- 改变日志、保存期限、审核、投诉、人工复核或标识机制；
- 发生重大投诉、安全事件、平台下架或主管部门问询；
- 生成式AI、算法、深度合成、内容标识或应用登记规则变化。

## 16. 质量指标

- 准入后被发现应走算法/模型备案路线的误判率；
- 模型及备案信息核验完整率；
- AI数据流未知项数量，目标为0；
- 标识、公示、投诉和人工复核阻断项关闭率；
- 50场景测试严重缺陷数量和关闭周期；
- 临时账号、密钥和权限撤销率，目标为100%；
- 交付后90日内因原版本遗漏发生的重大问题。

不得用“备案通过率”驱动员工隐瞒高风险功能，也不得把测试通过宣传为产品绝对安全。

- 已完成至少一个调用已备案模型的脱敏产品全链路演练；
- 已有监管分流、模型核验、数据流、标识、投诉、处置和测试模板；
- 已确定算法备案、安全评估、自研模型、特殊行业和数据跨境的升级专业人员；
- 已具备不接触生产密钥的测试方式；
- 已验证属地应用登记的当前材料、沟通和证据归档路径；
- 公开页面明确仅覆盖公众文本生成、最多2个已备案模型，不包含自研/微调和算法备案；
- 已确认价格不被宣传为政府收费或备案保证费。

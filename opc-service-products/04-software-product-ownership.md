# 软件产品权属确权

## 1. 产品卡

| 字段 | 内容 |
| --- | --- |
| 产品编号 | `OPC-ONCE-004` |
| 产品类型 | 专项服务 / 一次性交付 |
| 一句话结果 | 让一个核心软件产品的代码、贡献者、外包成果、开源依赖、域名和关键账号形成可追溯的权属证据链 |
| 标准服务费 | 人民币 8,800 元，含税 |
| 标准内部周期 | 材料齐备后 7–12 个工作日；软件著作权登记审查时间另计 |
| 标准容量 | 一个核心软件产品、一个主要代码仓库、最多3名贡献者/外包方、最多3份补正文件、一件普通软著申请 |
| 现有目录关系 | `S-06-02 软件、内容与成果权属清理包` 的软件专用收紧版本 |

## 2. 主要结果

用户最终获得的不是一张孤立的软件著作权证书，而是一套可以回答以下问题的证据包：

- 软件由谁、在什么关系下、使用什么既有材料完成；
- 创始人、员工、外包和合作方的成果如何进入当前主体；
- 哪些代码、模型、字体、图片、数据或组件来自第三方；
- 域名、代码仓库、云平台和应用商店账号由谁控制；
- 重大权属缺口是否已经补正，剩余风险如何升级；
- 软件著作权申请内容是否与真实版本一致。

## 3. 标准准入

### 3.1 可以进入

- 产品由一个中国大陆主体或拟设主体商业化；
- 有一个主要代码仓库和可以识别的版本；
- 核心贡献者、员工和外包方不超过3名/家；
- 尚未发生权属、抄袭、开源许可或侵权争议；
- 用户能够提供合同、付款、提交记录、版本历史或其他创作证据；
- 开源依赖数量和许可证复杂度处于普通应用水平；
- 用户愿意向Vault2077提供受控的只读代码或依赖清单。

### 3.2 必须升级

- 多家公司共同开发、联合实验室、学校或投资方主张权利；
- 有4名以上关键贡献者或历史人员无法联系；
- 存在GPL/AGPL、SSPL、Commons Clause等可能影响商业分发的重大许可问题；
- 使用来源不明的数据集、模型权重、素材或商业代码；
- 产品已被投诉、下架、发律师函或进入诉讼；
- 需要专利、集成电路布图、国际权利或商业秘密专项；
- 仓库规模、提交历史或资产数量明显超出标准容量。

### 3.3 不适用

- 尚无可识别的软件版本，仅有想法或产品原型；
- 只需要“包下证”而不愿核验真实作者和版本；
- 要求伪造开发时间、源代码、贡献者或权属文件；
- 只需要一次自动化开源扫描而不需要权属判断。

## 4. 服务范围

### 4.1 包含

1. 一个核心软件产品及主要版本的资产盘点；
2. 创始人、员工、外包和合作方贡献关系梳理；
3. 合同、付款、交付、提交和发布证据检查；
4. 一个主要仓库的提交者和主要目录抽样核验；
5. 依赖清单和高风险许可证初筛，不超过200个直接依赖记录；
6. 模型、字体、图片、数据、SDK和商业组件来源清单；
7. 域名、仓库、云平台、应用商店和主要运营账号控制权记录；
8. 权属链图、缺口和风险分级；
9. 不超过3份权属确认、转让、外包补充或既有材料声明文件；
10. 一件普通软件著作权申请材料和提交；
11. 最终软件产品权属证据包及维护日历。

### 4.2 不包含

- 全量代码审计、安全审计、渗透测试或代码质量评估；
- 对所有间接依赖逐一出具法律意见；
- 开源重大冲突整改、代码替换或架构改造；
- 专利检索、专利申请、商标、国际著作权或境外法律；
- 已发生的权属、侵权、离职、合作方或平台争议；
- 源代码鉴定、公证、时间戳、司法证据保全或技术调查；
- 软件著作权加急、测试报告、平台上架和认证；
- 超过3份补正文件或无法联系人员的谈判代理。

## 5. 用户材料

| 材料组 | 内容 | 齐备标准 |
| --- | --- | --- |
| 产品 | 产品名称、功能、发布日期、主要版本和商业用途 | 一个版本边界清楚 |
| 代码 | 主要仓库、提交历史、release/tag、构建说明 | 可只读访问或提供可验证导出 |
| 人员 | 创始人、员工、外包和合作方清单 | 角色、时间和贡献可描述 |
| 合同与付款 | 劳动、外包、采购、合作、付款和验收记录 | 与贡献关系能够对应 |
| 第三方资产 | 依赖、SDK、模型、数据、字体、图片和商业组件 | 来源和许可证尽可能齐全 |
| 账号 | 域名、仓库、云平台、应用商店和主要邮箱 | 当前控制人和恢复方式明确 |
| 登记 | 已有软著、商标、许可、上架和发布时间证据 | 文件完整或声明不存在 |

源代码无需通过普通邮件或聊天发送；应使用受控只读访问、脱敏导出或现场核验方式。

| 1. 资产盘点 | 建立产品、代码、第三方资产和账号清单 | 《软件资产总表》 | 关键资产无未知类别 | 1–2日 |

## 8. 验收标准

- 一个产品和一个主要版本的边界明确；
- 核心代码、贡献者、外包、第三方资产和账号均进入资产表；
- 每项核心成果都有当前权利人、证据状态和缺口等级；
- 不超过3个可处理的重大缺口已有签署文件或明确升级方案；
- 高风险开源、模型、数据和素材项不存在“未知且无人负责”的状态；
- 域名、仓库、云和应用商店账号有控制人及恢复路径；
- 一件软著申请按真实版本提交并交付凭证，或因用户决定不提交而形成书面记录；
- 用户收到最终报告、可编辑补正文件和证据索引。

软件著作权是否最终登记通过不作为Vault2077可保证的验收条件；材料真实性、提交和跟进记录才是服务验收项。

## 10. 修改和变更

- 包含两轮集中修改和一轮因原申请事实产生的标准补正；
- 更换软件名称但版本和权属不变可作为修改；更换核心版本、仓库或申请主体属于变更；
- 新发现贡献者、联合开发方或重大许可证问题时立即暂停并重新准入；
- 用户拒绝联系关键贡献者或补签文件，不得把未知权属标为已解决；
- 源代码和功能在申请期间实质变化时，必须重新确认申请版本。

## 11. 终止与退款节点

建议阶段结算：准入15%、资产盘点30%、权属链55%、补正文件75%、软著提交90%、最终报告100%。

因用户隐瞒贡献者、伪造时间或拒绝提供关键证据导致终止，按已完成阶段结算。因Vault2077未发现材料中明显存在的重大冲突，应免费重新核验；无法补救时退还未履行部分。

## 12. 异常与升级

以下情况不允许由运营人员自行给出“无风险”结论：

- 贡献者主张共同所有或拒绝确认；
- 仓库包含前雇主、客户或其他公司的代码；
- 关键组件的许可证限制商业分发、云服务或闭源使用；
- 模型权重、训练数据或素材来源无法说明；
- 已收到下架通知、侵权投诉或律师函；
- 用户要求删除、改写或伪造提交历史；
- 产品同时涉及专利、商业秘密或境外权利安排。

升级单应分别说明可继续处理的资产和必须交由律师、开源合规或技术审计人员处理的部分。

## 13. 运营 SOP

1. 核验订单并发送产品、人员、代码和第三方资产问卷；
2. 确认唯一主要版本和仓库，不在执行中无限扩大范围；
3. 建立资产总表，先记录事实再评价风险；
4. 抽样核对提交者、提交时间、合同、付款和发布记录；
5. 从锁文件、清单和构建配置生成依赖列表，由专业人员识别高风险项；
6. 核对域名、仓库、云和应用商店账号的组织归属与恢复方式；
7. 对可补正缺口生成文件，让真实权利人自行确认和签署；
8. 软著材料必须对应冻结版本，不使用虚假或拼接代码；
9. 第二人复核权属链、重大风险和软著申请信息；
10. 交付报告、索引和维护日历，关闭临时代码访问权限。

## 14. 源代码与秘密保护

- 优先使用只读、限时和最小范围的仓库访问；
- 不复制生产密钥、用户数据、环境变量和未公开商业秘密；
- 依赖清单和提交记录可导出时，不下载完整仓库；
- 服务完成后立即撤销临时访问，保留撤销记录；
- 交付报告不包含不必要的源代码片段或秘密值。

## 15. 交付后复查触发条件

- 新增核心贡献者、外包方或联合开发主体；
- 更换产品主体、仓库组织、域名或应用商店账号；
- 引入新的模型、数据集、商业组件或高风险开源许可证；
- 重大版本重写、开源发布、融资、并购或对外许可；
- 收到权属异议、平台投诉、下架或律师函。

## 16. 质量指标

- 核心资产证据覆盖率；
- 未知贡献者和未知来源资产数量；
- 补正文件签署完成率；
- 软著申请因信息错误产生的补正率；
- 服务结束时临时代码访问撤销率，目标为100%；
- 交付后90日内发现的重大遗漏。

- 已准备资产表、权属链、贡献者索引、依赖清单和控制权清单模板；

- 已确定开源重大冲突、侵权争议和专利事项的升级专业人员；
- 已建立只读代码访问、撤销和日志规范；
- 已验证普通软著申请材料和官方费用口径；

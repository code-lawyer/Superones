# Vault2077 OPC 服务台设计规格

## 1. 目标

OPC 把超级个体常见的经营支持分成两个清楚的责任边界：Vault2077 直接交付标准服务；外部独立顾问通过游骑兵协会展示并由用户直接联系。页面不得让用户误以为游骑兵由 Vault2077 雇用、定价或担保。

OPC 服务台标语固定为“超级个体，全栈运行”。标语和频道识别带之后的正式目录使用全站统一内容宽度，左右保留页面留白，但不得用四边细线把整个目录围成封闭盒子。目录三栏统一使用全站纸张底色，不得用彼此接近的灰白色制造局部组件岛；两条分栏细线从频道文字缎带下沿连续贯通至全站页脚上沿。窄屏改为纵向堆叠时，以贯穿内容宽度的横向细线表达相同结构。反色选中块不得停在无细线承接的版心边缘：第一栏左侧没有分栏线，因此其反色块必须从右侧分栏线一直延伸到浏览器视口左边缘；位于内部栏位的反色块则必须铺满相邻细线之间的完整宽度。任何反色块都不得成为四周留有缝隙的悬浮色块。

## 2. 三个一级入口

### 2.1 基础设施

基础设施是跨专业领域的完整标准交付。首版从完整需求池中优选以下七项高频、刚需且可标准化的经营底座：

1. 经营主体启动与首年治理
2. 财税与经营资金运行
3. 合同、交易与回款运行
4. 线上经营与平台准入
5. 用工与外部协作运行
6. 知识产权与数字资产运行
7. 数据、隐私与信息安全运行

名称表达经营能力，不按法律、财税等专业部门拆成一级导航。

七项是首版 SKU，不是永久不可变的数据库枚举。运营人员可以通过 OPC 菜单草稿增减、排序或修订具体项目；正式发布必须通过完整性校验。三个浏览分组“启动经营、上线与交付、持续安全运行”保持受控，避免后台演变为任意分类搭建器。完整需求池仍保留作后续版本研究，具体首版业务内容以 [OPC 服务清单](Vault2077-OPC-Service-Catalog.md) 为准。

### 2.2 专项服务

专项服务解决一个边界清楚的问题。首版优选十四项，并按六个面向 OPC 实际经营任务的专业领域辅助浏览：

- 法律与经营风险
- 财税与现金流
- 品牌与线上获客
- AI与企业数字化
- 用工与协作者
- 知识产权与产品商业化

专业领域只用于专项服务筛选，不替代“基础设施/专项服务”的一级结构。

### 2.3 游骑兵协会

游骑兵是外部独立顾问，按十种顾问身份浏览：

- 法律顾问
- 财税顾问
- 知识产权顾问
- 创业顾问
- 产品顾问
- 品牌顾问
- 自媒体专家
- 设计师
- 软件工程顾问
- AI 开发专家

六个专业领域不套用到游骑兵；顾问可以使用专长标签补充能力，但只选择一个主要顾问身份。

## 3. 标准服务合同

基础设施与专项服务均由 Vault2077 直接交付。每个服务修订必须包含：

- 名称与一句话结果；
- 服务类型和适用专业领域；
- 明确包含与不包含；
- 用户需提供的材料；
- 交付成果与交付形式；
- 可检查的验收标准；
- 标准周期；
- 固定价格或明确计价单位；
- 含税与第三方费用口径；
- 修订版本和公开状态。

每个公开服务详情提供无账号订单入口。用户确认服务名称、公开价格和范围后，选择自然人或法人/组织签约；法人/组织首期只支持法定代表人本人，不支持授权代理或内部审批链。签约方式区域只显示“电子签约”和“纸质签约”两个按钮：电子签约使用原生禁用按钮和灰色视觉，不添加“筹备中”“当前可用”或同义状态文案；纸质签约可以选择，当前订单只接受 `signatureMethod=paper`。

用户必须在付款前完整阅读并下载在线订单及预付款协议，主动确认服务快照、总价、真实收款主体、纸质合同确认前不启动服务，以及未完成纸质签约时全额原路退款且不扣除打印或寄送费用。服务器保存服务修订、价格、范围、周期、成果、付款金额、协议版本、协议哈希、确认时间、签约主体、加密联系人和加密寄送地址，然后为唯一订单号生成支付宝企业商户动态收银台。支付成功代表在线订单及预付款协议成立；纸质合同结果只控制是否放行履约，不作为付款后所有合同关系是否成立的条件。

下单流程不使用购物车，也不要求普通用户建立站内账户。浏览器付款返回页面、截图或用户声明不能改变到账状态；只有支付宝验真通知或主动查询可以确认到账。到账订单先进入“已付款待合同确认”，不得启动或消耗服务；受保护后台只记录“纸质合同门禁通过”或“发起全额退款”两种线上结论，不建设物流、寄送、返寄、提醒或纸质原件核验工作台。当前纸质签约入口的生产门禁依赖在线协议、支付宝支付/查询/退款/退款查询、持久化、加密和审计，不依赖 e 签宝配置。

支付宝动态收银台金额由服务器固定，用户不能自行输入；服务器仍必须在通知和查询时复核订单号、金额、APPID 与商户 PID。首次验真到账时，系统在同一事务冻结付款凭证并写入通知 outbox，随后异步向固定管理员邮箱 `lanzhouda@163.com` 发送订单摘要和受保护后台链接。邮件失败不得阻塞到账回调，必须重试并告警；邮件不得包含完整手机号、寄送地址或订单恢复凭证。

用户支付完成后可以查看和下载付款凭证图片。凭证列出服务快照、人民币实付金额、付款时间和支付宝交易号，我方名称与统一社会信用代码，用户签约主体资料，以及遮罩后的联系人和寄送地址；同时显示 `https://superones.top`、不含秘密参数的规范凭证路径、ICP 备案号“沪ICP备2026003401号-1”、凭证编号和校验摘要，并明确“付款凭证不替代发票”。图片正文必须包含网址和备案号，不依赖浏览器地址栏；不得把恢复令牌或完整敏感资料写入图片。

## 4. 游骑兵合同

公开职业档案只展示：

- 公开名称；
- 一个顾问身份；
- 可选的本人授权公开头像；
- 一句话介绍；
- 专长标签；
- 可选公开资质；
- 经本人授权的职业联系方式；
- 核验日期与资料更新时间。

用户直接联系顾问。Vault2077 不参与后续咨询、定价、付款、交付或争议处理，也不把统一工作人员联系方式放到游骑兵卡片上。页面必须持续显示独立关系声明。

头像只能由受保护后台上传。服务端解码并生成 320×320 与 800×800 两份 WebP，去除原图元数据后保存到 ADR-0016 规定的媒体存储；目录只保存不可变对象引用。后台不接受任意第三方图片 URL，未上传头像时继续使用非人物化占位肖像。

## 5. 页面与路由

- `/opc`：唯一公开工作台，通过 `view=infrastructure|specialties|rangers` 恢复三个一级视图，不建立重复分类页面。
- 基础设施与专项服务不设置独立详情页；用户在 `/opc` 工作台内直接展开具体服务。
- 服务使用稳定 slug 写入工作台查询参数（例如 `/opc?view=infrastructure&service=<slug>`），名称修改不影响入口；查询参数只负责恢复选中状态，不复制一套详情页面。
- 游骑兵公开档案使用稳定的 `/opc/rangers/[slug]` 个人详情路由，详情 URL 不随公开名称修改而变化。

桌面端和移动端共用同一工作台信息结构；移动端只改变分栏排列，不以独立详情页作为兼容方案。

## 6. 数据与运营

- OPC 是全站唯一允许后台直接维护公开目录正文的产品频道；可编辑对象只包括基础设施、专项服务和游骑兵公开档案。Vault 资讯、来源事实、SiC 内容与平台榜、Frontier 排名继续由各自自动管线产生，后台不得用同一编辑接口改写。
- 后台编辑草稿，公开页面只读取最近一次已发布快照。保存草稿不改变前台；发布要求二次确认、乐观版本检查、字段完整性校验和不可变审计记录。
- 后台支持新增、删除、排序和编辑具体项目，但不允许任意增加一级入口、专项专业领域、基础设施浏览分组或游骑兵身份。分类法变化必须先修改本规格。
- 已发布服务修订不可静默覆盖；新订单在服务器创建时绑定当时的已发布修订，修订不作为用户展示字段。
- 订单创建时保存服务类型、slug、编号、名称、修订、公开价格、范围、周期、成果、付款金额、签约方式、在线协议版本、协议 SHA-256 和确认时间快照；支付后保存付款交易号、交易状态与必要核验时间。后续目录、协议或价格修改不改变历史订单。未来电子签订单另按 ADR-0018 保存模板、流程和电子归档证据。
- 首次验真到账时为订单生成唯一不可变付款凭证快照、凭证编号与 SHA-256，并写入唯一 `payment_confirmed` outbox 事件；重复支付宝通知不得重复生成凭证或邮件。
- 签约方、订单联系方式和寄送地址使用数据密钥环加密，只在受保护后台用于纸质签约、付款/退款、联系和交付。未付款取消订单满 90 天清除地址和联系人；已付款订单完成或退款满 24 个月后清除非合同联系方式和地址。
- `待付款 → 已付款待合同确认` 只由支付宝经过验证的服务器通知或主动交易查询驱动；`已付款待合同确认 → 已到账可履约` 只由最近五分钟再认证的后台合同结论驱动；`已付款待合同确认/已到账可履约 → 退款处理中 → 已退款` 必须经过支付宝全额退款和退款结果核验。付款异常不得正常交付，后台不能任意写目标状态。完成、合同结论、退款、后台主动查询和联系方式导出均要求最近五分钟再认证并留下审计记录。
- 每次发布保存带修订号和时间的完整目录快照；删除只影响新公开目录，历史发布快照继续可追溯。
- 下架服务不接受新订单，但历史订单仍可追溯。
- 顾问资料必须有授权、核验和撤回流程；撤回后公开页面停止展示。
- 价格、法律声明、真实顾问资料与收款方式属于上线前业务输入，不能用演示数据冒充。
- 公开页面不展示内部备注、私人联系方式、适用性判断或运营状态。

## 7. 状态与验收

- 三入口在桌面与移动端均可直接到达。
- 首版目录以七项基础设施和十四项专项服务初始化，后续项目增减必须来自有审计记录的 OPC 菜单发布；专项服务只用六个专业领域，游骑兵只用十个顾问身份。
- 服务卡和顾问卡的责任主体、联系对象和行动文案不会混淆。
- 未登录用户不能读取草稿；保存草稿不改变前台，版本冲突不会覆盖他人修改，字段不完整或仍为占位内容时不能发布。
- 空列表、已下架、资料过期、联系入口不可用均有明确状态。
- 标准宽度 `360 / 768 / 1280 / 1440` 无横向溢出，筛选可键盘操作。
- 页面不出现旧六分类、购物车或游骑兵统一客服入口；标准服务详情必须提供联系方式登记与付款入口。
- 签约方式只有两个按钮；电子签约仅以灰色原生禁用状态表达不可操作，页面不出现签约方式状态标签或解释文案。
- 用户付款前可以完整阅读和下载在线订单及预付款协议；支付后状态只能由支付宝服务器证据、后台合同结论和支付宝退款证据推进。
- 验真到账后用户可以查看并下载付款凭证图片，服务、金额、双方主体、网址和 ICP 备案号与服务器锁定快照一致，图片不泄露恢复凭证或完整联系地址。
- 后台订单 dossier 贯通服务/协议、签约主体、联系地址、付款、凭证、合同结论、退款和审计；完整联系信息需要最近五分钟再认证，付款邮件只提供摘要和后台安全链接。

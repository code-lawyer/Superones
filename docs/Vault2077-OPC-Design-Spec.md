# Vault2077 OPC 服务台设计规格

## 1. 目标

OPC 把超级个体常见的经营支持分成两个清楚的责任边界：Vault2077 直接交付标准服务；外部独立顾问通过游骑兵协会展示并由用户直接联系。页面不得让用户误以为游骑兵由 Vault2077 雇用、定价或担保。

OPC 服务台标语固定为“超级个体，全栈运行”。标语和频道识别带之后的正式目录使用全站统一内容宽度，左右保留页面留白，但不得用四边细线把整个目录围成封闭盒子。目录三栏统一使用全站纸张底色，不得用彼此接近的灰白色制造局部组件岛；两条分栏细线从频道文字缎带下沿连续贯通至全站页脚上沿。窄屏改为纵向堆叠时，以贯穿内容宽度的横向细线表达相同结构。反色选中块不得停在无细线承接的版心边缘：第一栏左侧没有分栏线，因此其反色块必须从右侧分栏线一直延伸到浏览器视口左边缘；位于内部栏位的反色块则必须铺满相邻细线之间的完整宽度。任何反色块都不得成为四周留有缝隙的悬浮色块。

## 2. 三个一级入口

### 2.1 基础设施

基础设施是跨专业领域的完整标准交付。首版从完整需求池中优选以下七项高频、刚需且可标准化的经营底座：

1. 经营主体启动与首年治理
2. 财税与经营资金运行
3. 合同、交易与回款运行
4. 线上经营与平台准入
5. 用工与外部协作运行
6. 知识产权与数字资产运行
7. 数据、隐私与信息安全运行

名称表达经营能力，不按法律、财税等专业部门拆成一级导航。

七项是首版 SKU，不是永久不可变的数据库枚举。运营人员可以通过 OPC 菜单草稿增减、排序或修订具体项目；正式发布必须通过完整性和专业复核门禁。三个浏览分组“启动经营、上线与交付、持续安全运行”保持受控，避免后台演变为任意分类搭建器。完整需求池仍保留作后续版本研究，具体首版业务内容以 [OPC 服务清单](Vault2077-OPC-Service-Catalog.md) 为准。

### 2.2 专项服务

专项服务解决一个边界清楚的问题。首版优选十四项，并按六个面向 OPC 实际经营任务的专业领域辅助浏览：

- 法律与经营风险
- 财税与现金流
- 品牌与线上获客
- AI与企业数字化
- 用工与协作者
- 知识产权与产品商业化

专业领域只用于专项服务筛选，不替代“基础设施/专项服务”的一级结构。

### 2.3 游骑兵协会

游骑兵是外部独立顾问，按十种顾问身份浏览：

- 法律顾问
- 财税顾问
- 知识产权顾问
- 创业顾问
- 产品顾问
- 品牌顾问
- 自媒体专家
- 设计师
- 软件工程顾问
- AI 开发专家

六个专业领域不套用到游骑兵；顾问可以使用专长标签补充能力，但只选择一个主要顾问身份。

## 3. 标准服务合同

基础设施与专项服务均由 Vault2077 直接交付。每个服务修订必须包含：

- 名称与一句话结果；
- 服务类型和适用专业领域；
- 明确包含与不包含；
- 用户需提供的材料；
- 交付成果与交付形式；
- 交付角色与分工；
- 可检查的验收标准；
- 标准周期；
- 固定价格或明确计价单位；
- 含税与第三方费用口径；
- 专业复核说明和修订生效时间。

用户先发起咨询，工作人员完成适用性确认后再安排付款和交付。公开界面使用“咨询此服务”“确认是否适用”等表述，不使用“购买”“立即下单”或购物车隐喻。

## 4. 游骑兵合同

公开职业档案只展示：

- 公开名称；
- 一个顾问身份；
- 一句话介绍；
- 专长标签；
- 可选公开资质；
- 经本人授权的职业联系方式；
- 核验日期与资料更新时间。

用户直接联系顾问。Vault2077 不参与后续咨询、定价、付款、交付或争议处理，也不把统一工作人员联系方式放到游骑兵卡片上。页面必须持续显示独立关系声明。

## 5. 页面与路由

- `/opc`：三入口总览。
- `/opc/infrastructure`：基础设施列表。
- `/opc/specialties`：专项服务及六领域筛选。
- `/opc/rangers`：游骑兵及十身份筛选。
- 基础设施与专项服务不设置独立详情页；用户从分类页进入 `/opc` 工作台，并在同一页面内直接展开具体服务。
- 服务使用稳定 slug 写入工作台查询参数（例如 `/opc?view=infrastructure&service=<slug>`），名称修改不影响入口；查询参数只负责恢复选中状态，不复制一套详情页面。
- 游骑兵公开档案可以保留稳定的个人详情路由，详情 URL 不随公开名称修改而变化。

桌面端和移动端共用同一工作台信息结构；移动端只改变分栏排列，不以独立详情页作为兼容方案。

## 6. 数据与运营

- OPC 是全站唯一允许后台直接维护公开目录正文的产品频道；可编辑对象只包括基础设施、专项服务和游骑兵公开档案。Vault 资讯、来源事实、SiC 内容与平台榜、Frontier 排名继续由各自自动管线产生，后台不得用同一编辑接口改写。
- 后台编辑草稿，公开页面只读取最近一次已发布快照。保存草稿不改变前台；发布要求二次确认、乐观版本检查、字段完整性校验和不可变审计记录。
- 后台支持新增、删除、排序和编辑具体项目，但不允许任意增加一级入口、专项专业领域、基础设施浏览分组或游骑兵身份。分类法变化必须先修改本规格。
- 已发布服务修订不可静默覆盖；新咨询记录所看到的修订。
- 每次发布保存带修订号和时间的完整目录快照；删除只影响新公开目录，历史发布快照继续可追溯。
- 下架服务不接受新咨询，但历史记录仍可追溯。
- 顾问资料必须有授权、核验和撤回流程；撤回后公开页面停止展示。
- 价格、法律声明、真实顾问资料与收款方式属于上线前业务输入，不能用演示数据冒充。
- 公开页面不展示内部备注、私人联系方式、适用性判断或运营状态。

## 7. 状态与验收

- 三入口在桌面与移动端均可直接到达。
- 首版目录以七项基础设施和十四项专项服务初始化，后续项目增减必须来自有审计记录的 OPC 菜单发布；专项服务只用六个专业领域，游骑兵只用十个顾问身份。
- 服务卡和顾问卡的责任主体、联系对象和行动文案不会混淆。
- 未登录用户不能读取草稿；保存草稿不改变前台，版本冲突不会覆盖他人修改，字段不完整或仍为占位内容时不能发布。
- 空列表、已下架、资料过期、联系入口不可用均有明确状态。
- 标准宽度 `360 / 768 / 1280 / 1440` 无横向溢出，筛选可键盘操作。
- 页面不出现旧六分类、购买按钮或游骑兵统一客服入口。

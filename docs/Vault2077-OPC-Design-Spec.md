# Vault2077 OPC 服务台设计规格

## 1. 目标

OPC 把超级个体常见的经营支持分成两个清楚的责任边界：Vault2077 直接交付标准服务；外部独立顾问通过游骑兵协会展示并由用户直接联系。页面不得让用户误以为游骑兵由 Vault2077 雇用、定价或担保。

OPC 服务台标语固定为“超级个体，全栈运行”。标语和频道识别带之后的正式目录使用全站统一内容宽度，左右保留页面留白，但不得用四边细线把整个目录围成封闭盒子。目录三栏统一使用全站纸张底色，不得用彼此接近的灰白色制造局部组件岛；两条分栏细线从频道文字缎带下沿连续贯通至全站页脚上沿。窄屏改为纵向堆叠时，以贯穿内容宽度的横向细线表达相同结构。反色选中块不得停在无细线承接的版心边缘：第一栏左侧没有分栏线，因此其反色块必须从右侧分栏线一直延伸到浏览器视口左边缘；位于内部栏位的反色块则必须铺满相邻细线之间的完整宽度。任何反色块都不得成为四周留有缝隙的悬浮色块。

## 2. 三个一级入口

### 2.1 基础设施

基础设施是跨专业领域的完整标准交付。首版从完整需求池中优选以下七项高频、刚需且可标准化的经营底座：

1. 经营主体启动与首年治理
2. 财税与经营资金运行
3. 合同、交易与回款运行
4. 线上经营与平台准入
5. 用工与外部协作运行
6. 知识产权与数字资产运行
7. 数据、隐私与信息安全运行

名称表达经营能力，不按法律、财税等专业部门拆成一级导航。

七项是首版 SKU，不是永久不可变的数据库枚举。运营人员可以通过 OPC 菜单草稿增减、排序或修订具体项目；正式发布必须通过完整性校验。三个浏览分组“启动经营、上线与交付、持续安全运行”保持受控，避免后台演变为任意分类搭建器。完整需求池仍保留作后续版本研究，具体首版业务内容以 [OPC 服务清单](Vault2077-OPC-Service-Catalog.md) 为准。

### 2.2 专项服务

专项服务解决一个边界清楚的问题。首版优选十四项，并按六个面向 OPC 实际经营任务的专业领域辅助浏览：

- 法律与经营风险
- 财税与现金流
- 品牌与线上获客
- AI与企业数字化
- 用工与协作者
- 知识产权与产品商业化

专业领域只用于专项服务筛选，不替代“基础设施/专项服务”的一级结构。

### 2.3 游骑兵协会

游骑兵是外部独立顾问，按十种顾问身份浏览：

- 法律顾问
- 财税顾问
- 知识产权顾问
- 创业顾问
- 产品顾问
- 品牌顾问
- 自媒体专家
- 设计师
- 软件工程顾问
- AI 开发专家

六个专业领域不套用到游骑兵；顾问可以使用专长标签补充能力，但只选择一个主要顾问身份。

## 3. 标准服务合同

基础设施与专项服务均由 Vault2077 直接交付。每个服务修订必须包含：

- 名称与一句话结果；
- 服务类型和适用专业领域；
- 明确包含与不包含；
- 用户需提供的材料；
- 交付成果与交付形式；
- 可检查的验收标准；
- 标准周期；
- 固定价格或明确计价单位；
- 含税与第三方费用口径；
- 修订版本和公开状态。

每个公开服务详情提供无账号订单入口。用户确认服务名称、公开价格和范围后，选择自然人或法人/组织作为付款／委托方；法人/组织首期只支持法定代表人本人，不支持授权代理或内部审批链。付款方式区域显示“线上付款”和“线下付款”两个按钮：线上付款明确显示“暂未开放”并保持禁用；线下付款选择“对公转账”。

线下付款页在转账前同页展示企业收款户名、开户银行、支行、账号和可选联行号，服务协议的查看弹窗与 PDF 下载入口，以及不带姓名、职务或介绍的联系人二维码。用户不必先转账再添加联系人，可以在转账前扫码沟通确认。提交表单只生成唯一订单号和同值付款附言，不自动扣款、不跳转支付宝，也不收集纸质合同寄送地址。

用户必须在提交前完整查看并可下载服务订单及线下对公转账协议，主动确认服务快照、固定总价、真实企业收款主体和到账核验规则。用户勾选并提交后订单协议成立；服务启动仍以企业银行实际到账核验和必要项目确认为条件。服务器保存服务、金额、协议正文/版本/SHA-256/确认时间、付款资料修订、企业账户快照、PDF 与二维码 SHA-256，以及加密付款方和联系人。后续替换公开资料不改变历史订单。

浏览器页面、截图、回单图片或用户声明不能改变到账状态。最近五分钟完成再认证的管理员必须按企业银行实际入账记录核对订单固定金额、付款户名、唯一银行流水号和入账时间；金额不一致、流水重复、订单版本陈旧或证据不完整时拒绝确认。付款户名加密保存，审计只保留流水指纹。首次确认到账时，系统冻结付款凭证并写入唯一通知 outbox，邮件不得包含完整联系人、付款户名、账号或恢复凭证。

用户到账后可以查看和下载付款凭证图片。凭证列出服务快照、人民币实付金额、付款时间和银行流水号，我方名称与统一社会信用代码，用户委托主体资料和遮罩联系人；同时显示规范网址、ICP 备案号、凭证编号和校验摘要，并明确“付款凭证不替代发票”。图片不得写成支付宝付款或纸质合同凭证，也不得包含恢复令牌、企业银行完整账号或完整敏感资料。

## 4. 游骑兵合同

公开职业档案只展示：

- 公开名称；
- 一个顾问身份；
- 可选的本人授权公开头像；
- 一句话介绍；
- 专长标签；
- 可选公开资质；
- 经本人授权的职业联系方式；
- 核验日期与资料更新时间。

用户直接联系顾问。Vault2077 不参与后续咨询、定价、付款、交付或争议处理，也不把统一工作人员联系方式放到游骑兵卡片上。页面必须持续显示独立关系声明。

头像只能由受保护后台上传。服务端解码并生成 320×320 与 800×800 两份 WebP，去除原图元数据后保存到 ADR-0016 规定的媒体存储；目录只保存不可变对象引用。后台不接受任意第三方图片 URL，未上传头像时继续使用非人物化占位肖像。

## 5. 页面与路由

- `/opc`：唯一公开工作台，通过 `view=infrastructure|specialties|rangers` 恢复三个一级视图，不建立重复分类页面。
- 基础设施与专项服务不设置独立详情页；用户在 `/opc` 工作台内直接展开具体服务。
- 服务使用稳定 slug 写入工作台查询参数（例如 `/opc?view=infrastructure&service=<slug>`），名称修改不影响入口；查询参数只负责恢复选中状态，不复制一套详情页面。
- 游骑兵公开档案使用稳定的 `/opc/rangers/[slug]` 个人详情路由，详情 URL 不随公开名称修改而变化。

桌面端和移动端共用同一工作台信息结构；移动端只改变分栏排列，不以独立详情页作为兼容方案。

## 6. 数据与运营

- OPC 是全站唯一允许后台直接维护公开目录正文的产品频道；可编辑对象只包括基础设施、专项服务和游骑兵公开档案。Vault 资讯、来源事实、SiC 内容与平台榜、Frontier 排名继续由各自自动管线产生，后台不得用同一编辑接口改写。
- 后台编辑草稿，公开页面只读取最近一次已发布快照。保存草稿不改变前台；发布要求二次确认、乐观版本检查、字段完整性校验和不可变审计记录。
- 后台支持新增、删除、排序和编辑具体项目，但不允许任意增加一级入口、专项专业领域、基础设施浏览分组或游骑兵身份。分类法变化必须先修改本规格。
- 已发布服务修订不可静默覆盖；新订单在服务器创建时绑定当时的已发布修订，修订不作为用户展示字段。
- 新订单创建时保存服务类型、slug、编号、名称、修订、公开价格、范围、周期、成果、固定金额、在线协议正文/版本/SHA-256/确认时间、付款资料修订、企业账户快照、PDF 与二维码 SHA-256；银行核验后保存唯一流水号、加密付款户名、入账时间和核验时间。后续目录、协议、账户或二维码修改不改变历史订单。
- 企业账户、协议 PDF 与二维码必须作为同一修订原子发布到 PostgreSQL；VPS 文件只是替换暂存输入，现有头像和合同 OSS 均不存放本资料。
- 同一付款资料修订不得覆盖不同内容；资产 URL 的 SHA-256 必须与服务器当前修订匹配，旧页面不得混用新 PDF 或二维码。用户生成订单后和页面刷新后都能从当前浏览器进入付款状态/凭证页。
- 首次银行到账确认时为订单生成唯一不可变付款凭证快照、凭证编号与 SHA-256，并写入唯一 `payment_confirmed` outbox 事件；重复流水号不能绑定第二个订单或生成第二份凭证。
- 银行流水号在保存、判重和审计指纹前统一规范化；尚未确认到账的银行订单可由最近五分钟再认证的后台取消，取消记录与审计原子提交并进入 90 天联系人清理。
- 付款／委托方和订单联系方式使用数据密钥环加密，只在受保护后台用于到账核验、联系和交付。未付款取消订单满 90 天清除联系人；已付款订单完成或退款满 24 个月后清除非合同联系方式。
- 新订单 `待付款 → 已到账可履约` 只由最近五分钟再认证的后台银行证据核验驱动；`已到账可履约 → 已完成` 由后台交付结论驱动。线下退款尚未形成自动状态机，不能调用支付宝退款或以普通状态修改伪造退款完成。既有支付宝／纸质订单继续按 ADR-0019 处理，两个提供方的证据不得交叉推进。
- 每次发布保存带修订号和时间的完整目录快照；删除只影响新公开目录，历史发布快照继续可追溯。
- 下架服务不接受新订单，但历史订单仍可追溯。
- 顾问资料必须有授权、核验和撤回流程；撤回后公开页面停止展示。
- 价格、法律声明、真实顾问资料与收款方式属于上线前业务输入，不能用演示数据冒充。
- 公开页面不展示内部备注、私人联系方式、适用性判断或运营状态。

## 7. 状态与验收

- 三入口在桌面与移动端均可直接到达。
- 首版目录以七项基础设施和十四项专项服务初始化，后续项目增减必须来自有审计记录的 OPC 菜单发布；专项服务只用六个专业领域，游骑兵只用十个顾问身份。
- 服务卡和顾问卡的责任主体、联系对象和行动文案不会混淆。
- 未登录用户不能读取草稿；保存草稿不改变前台，版本冲突不会覆盖他人修改，字段不完整或仍为占位内容时不能发布。
- 空列表、已下架、资料过期、联系入口不可用均有明确状态。
- 标准宽度 `360 / 768 / 1280 / 1440` 无横向溢出，筛选可键盘操作。
- 页面不出现旧六分类、购物车或游骑兵统一客服入口；标准服务详情必须提供联系方式登记与付款入口。
- 付款方式只有两个按钮；线上付款明确显示“暂未开放”并禁用，线下对公转账可选。
- 企业账户、协议弹窗/PDF 下载和联系人二维码在转账前同页可见；二维码没有联系人介绍，用户可先扫码再决定转账。
- 用户提交前可以完整查看和下载协议；提交后生成唯一订单号/付款附言且不跳转第三方收银台，到账只由后台银行实际入账证据推进。
- 付款单生成后页面直接提供付款状态与凭证入口；同一浏览器刷新后仍可进入最近订单状态页。
- 银行核验后用户可以查看并下载付款凭证图片，服务、金额、双方主体、网址和 ICP 备案号与服务器锁定快照一致，图片不泄露恢复凭证、付款户名或完整联系信息。
- 后台订单 dossier 贯通服务/协议、付款资料修订、企业账户快照、付款方、银行流水、凭证和审计；完整联系信息需要最近五分钟再认证，付款邮件只提供摘要和后台安全链接。

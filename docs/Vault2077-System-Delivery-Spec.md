# Vault2077 系统交付规格

## 1. 范围与原则

本规格把产品规格和 ADR 转为首个生产版本的工程合同。当前仓库可以使用演示数据和文件适配器预览，但只有满足本规格与上线清单后才可处理真实报名、自动发布和赛季结算。

系统边界：

- 公开站：读取已发布内容和公开业务数据。
- 运营后台：处理人工输入、异常和诊断。
- 统一采集器：读取通用境外公开内容、平台原生榜和 Frontier 回退任务。
- 境内处理端：验证批次、持久化、调用编辑处理、发布。
- Frontier GitHub 集成：境内服务端读取已知公开参赛仓库，失败时转统一采集器回退。
- PostgreSQL：生产写模型与任务状态的唯一事实源。

## 2. 统一采集

### 2.1 单一实现，四个通道

仓库只能保留一个境外采集 workflow 文件、一个采集入口和一种签名交付协议。它必须支持四个独立通道：

| 通道 | 基准节奏（北京时间） | 重叠窗口 | 境内编辑处理 | 职责 |
| --- | --- | --- | --- | --- |
| `information` | 偶数小时 `:05` | 12h | 是 | 正式资讯 |
| `roadside` | 偶数小时 `:55` | 12h | 是 | 个人/社区发布 |
| `sic` | `07:25`、`19:25` | 24h | 是 | SiC 内容组 |
| `rankings` | 每小时唤醒 | 按提供方/任务 | 否 | 平台原生榜与 Frontier 回退任务 |

通道必须分别记录运行、重试、失败与最后成功时间。一个通道失败不得阻塞其他通道。

### 2.2 来源边界

- 采集器只读取版本化来源注册表中获准的公开来源。
- information、roadside、sic 产生内容记录；rankings 只产生平台顺序、公开仓库观察和公开任务结果。
- GitHub Trending、Hugging Face Trending、OpenRouter `top-weekly`、skills.sh 原生视图保持提供方顺序。
- 不采集 MCP 排名，不计算本地增长榜。
- 通用内容与平台榜的境外读取在采集器侧执行。Frontier 是唯一例外：境内服务端可以按当前参赛名单读取已知公开 GitHub 仓库；浏览器和普通页面不得直连，失败必须保持可恢复状态并转异步公开任务。

## 3. 交付协议

### 3.1 `AcquisitionBatch v1`

统一批次至少包含：

- `schemaVersion`
- `batchId`
- `lane`
- `scheduleId`
- `sourceBundleRevision`
- `windowStartedAt` / `windowEndedAt`
- `generatedAt`
- `records`
- `sourceReports`

record kind 只允许当前注册表批准的类型，例如 `information`、`publication`、`entity_profile`、`repository_observation`、`ranking_observation`。每条记录保留稳定来源 ID、原始 URL、原始发布时间、内容散列和来源特定字段。

### 3.2 签名与防重放

采集器对原始请求体使用共享密钥签名。境内 `POST /api/internal/acquisition` 必须验证：

- 签名与常量时间比较；
- 时间戳允许窗口；
- `batchId` 幂等；
- `scheduleId` 和 lane 合法；
- `sourceBundleRevision` 在部署白名单内；
- 请求大小、记录数量、URL 与字段长度限制。

验证失败不得写入正式 inbox。处理入口 `POST /api/internal/acquisition/process` 使用独立 worker 密钥或明确配置的同源密钥。

旧 `/api/internal/content`、`/api/internal/sic/content`、`/api/internal/sic/snapshot` 仅可在迁移期读取或返回弃用响应，不得成为规范生产入口。

## 4. Inbox 与处理状态

批次状态固定为：

`received → processing → processed`

失败进入 `retryable` 或 `quarantined`；超过重试预算、schema 不支持、来源修订未知或内容违反硬约束时进入隔离。状态转换、尝试次数、错误分类和时间必须持久化并可审计。

同一时刻生产环境只允许一个发布写者处理 inbox。worker 在发布完成后原子提交业务写模型与批次状态，防止页面看见半批结果。

## 5. 内容与榜单处理

### 5.1 内容通道

境内处理端负责翻译、单条摘要、事件匹配与 SiC 编辑说明。原始字段不可被处理结果覆盖；处理结果必须记录处理版本，失败可重试而不重复发布。

### 5.2 rankings 通道

平台榜不进入编辑模型，不跨平台重排。每个结果保存平台、视图、平台内顺序、原始链接、采集时间和平台公开字段。

Frontier 使用境内 GitHub 快速路径与同一通道的异步回退：

1. 报名先写入境内事实源并立即显示待验证状态。
2. 境内服务端使用服务端凭证、短超时和限流读取公开仓库；成功后记录来源、时间和快照并推进状态。
3. 每小时后台任务从境内事实源读取当前已验证参赛名单，批量形成 Star 快照；普通页面只读取最近一次成功快照。
4. 暂时不可达、限流或部分失败时，保留待验证状态或上一成功值，并写入只含公开仓库信息和防重放字段的公开任务。
5. 采集器执行回退任务，以签名 `repository_observation` 回传；境内验证后推进报名、排行榜或结算。

GitHub 直读不得执行写操作。私人邮箱、后台备注和运营资料不得进入 GitHub 请求、公开任务或采集产物。

## 6. 数据与存储

### 6.1 预览

文件适配器仅支持本地开发、演示和单写者预览。页面必须标明演示/降级状态，不得把文件回退数据作为生产事实。

### 6.2 生产 v1

真实业务启用前必须完成：

- PostgreSQL 存储内容、事件、OPC 修订、边境报名/奖品/结算、公开任务、inbox 与审计日志；
- 数据迁移、约束、事务和恢复演练；
- 加密保存私人邮箱及最小化访问；
- 自动备份、保留策略和恢复点目标有证据。

Redis 仅在需要分布式锁、缓存或队列吞吐时加入；对象存储仅在原始包/归档体量需要时加入。二者不是首个生产版本的强制依赖。

## 7. 公开站与后台

- 公开路由不得读取原始采集包、错误堆栈或密钥。
- `/pipeline` 必须限制为本地或认证后台诊断，不进入 sitemap、公开导航或搜索索引。
- 生产错误不得静默回退到演示数据；公开页面显示可理解的降级状态。
- 后台共享密码必须使用抗离线破解的哈希；会话 `HttpOnly`、`Secure`、`SameSite=Strict`，有绝对与空闲过期。
- 登录有速率限制/锁定；所有写操作二次确认并写不可变审计日志。

## 8. 安全与可靠性

- 设置 CSP、HSTS、`X-Content-Type-Options`、Referrer Policy 与最小权限 CORS。
- 所有外部输入做 schema、长度、URL、字符集与数量限制。
- 密钥只来自部署秘密，不进入日志、构建产物或客户端。
- 采集器和处理端分别有超时、限流、指数退避与最大尝试次数。
- 监控至少覆盖：通道新鲜度、批次拒绝、处理积压、隔离量、发布延迟、边境任务延迟、备份与恢复演练。

## 9. 交付证据

每次候选发布必须提供：

- `npm run docs:check`
- `npm run typecheck`
- 单元测试和采集器测试
- 生产构建
- 统一采集 inbox E2E
- 内容发布 E2E
- 四种标准宽度的关键页面检查
- 安全头、后台鉴权、幂等/重放、备份恢复和降级行为证据

测试数量不是规范；实际数量只记录在实现追踪矩阵。

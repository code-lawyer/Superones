# OPC 下单后、付款扫码前签署电子服务协议可行性调研

> 调研日期：2026-08-01
> 范围：中国大陆境内的 OPC 标准服务订单；用户无 Vault2077 账号；订单登记后、进入付款页面或显示付款码前，先完成电子服务协议签署。
> 证据原则：法律与司法解释只使用政府、法院官方全文；厂商能力只使用厂商官方开放平台或腾讯云官方文档。本文是产品与工程可行性研究，不替代对最终合同文本、签署主体和具体业务资质的专项法律意见。

## 结论先行

功能**可实现，法律路径成熟，工程难度中等，业务与合规落地难度中等偏高**。

调用电子签厂商 API、生成 H5 签署链接本身不难。本段调研形成时，项目曾有无账号订单、服务/价格快照、加密联系方式和第三方在线付款编排；该在线付款实现后来已按 ADR-0022 退役。现行证据见 [`app/api/opc/orders/route.ts`](../../app/api/opc/orders/route.ts)、[`components/opc-order-entry.tsx`](../../components/opc-order-entry.tsx)、[`lib/opc-order-store.ts`](../../lib/opc-order-store.ts) 和 [`ADR-0022`](../adr/0022-retire-online-payment-integration.md)。

建议首选**单一厂商的 API + 厂商托管 H5 全页跳转**，而不是自己实现电子签名，也不建议首版用 iframe 强嵌入。e签宝的公开 API 文档、H5 签署链路、模板、回调、下载与公开按份价格较完整，适合先做技术验证；如果未来以微信小程序/企业微信为主，腾讯电子签也可作为备选。最终选型仍应以正式报价、数据处理协议、服务等级、出证费用和沙箱联调结果为准。

在合同文本、签约主体、企业电子印章授权和隐私合规材料已经准备好的前提下，估计一名熟悉本项目的全栈工程师完成单厂商、单合同模板、自然人签署的生产 MVP 需要 **2—4 周**；同时支持自然人与企业客户、异常补偿、完整后台证据管理，通常需要 **4—8 周**。这是基于当前代码面的工程估算，不是厂商承诺；企业认证、商务签约和印章授权另有外部前置时间。

## 1. 法律与证据可行性

### 1.1 普通 OPC 服务协议可以使用电子签名

《中华人民共和国电子签名法》第三条允许民事活动中的合同约定使用电子签名和数据电文，并规定不得仅因电子形式否定效力；普通商业服务协议不属于该条列出的婚姻、收养、继承、公用事业停止服务等排除场景。第四至六条规定了数据电文满足书面、原件和保存要求的条件；第十三条规定可靠电子签名必须满足签名数据专有、签署时由签名人控制、签名和正文修改可被发现，第十四条明确可靠电子签名与手写签名或盖章具有同等法律效力。[工业和信息化部：《中华人民共和国电子签名法（2019年修正）》](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_e3f623f70c23497e88a941170093446a.html)

因此，产品目标不应只是显示一张手写签名图片，而应使用能够完成身份识别、签署意愿认证、数字证书签名、文件防篡改和全过程留痕的可靠电子签名方案。电子签厂商不是让合同当然有效的“背书方”；合同主体、意思表示、条款内容和签署权限仍需分别成立。

### 1.2 必须重新约定合同成立时点

《民法典》第四百九十一条规定，通过信息网络发布的服务信息符合要约条件时，对方选择服务并提交订单成功，原则上合同即成立，但当事人另有约定的除外；第四百九十条又规定，采用合同书形式时一般在各方签名、盖章或按指印时成立。[中央网信办：《中华人民共和国民法典》，第490—491条](https://www.cac.gov.cn/2020-06/01/c_15925617772683192.htm)

当前页面写的是“提交后会生成待付款订单”，后台也写明提交联系方式即形成待付款订单。加入电子签后，应在服务详情、下单页和协议中一致说明：

- 提交订单只是发起签约申请并冻结服务/价格快照；
- 服务合同在客户与实际服务提供主体均完成电子签署时成立，或按最终法律审核确定的时点成立；
- 未签、拒签、过期不进入付款；
- 付款后何时开始服务、取消和退款如何处理。

否则可能出现“下单时已经成立一个合同，电子签又成立另一个合同”的双重文本与版本冲突。

### 1.3 标准协议的重大条款不能只藏在 PDF 里

该服务协议会是平台预先拟定、重复使用的格式条款。《民法典》第四百九十六条要求提供方公平确定权利义务，并以合理方式提示免责、责任限制等与对方有重大利害关系的条款，按要求予以说明；第四百九十七条规定不合理免责、加重对方责任或排除对方主要权利的条款无效。[中央网信办：《中华人民共和国民法典》，第496—498条](https://www.cac.gov.cn/2020-06/01/c_15925617772683192.htm)

产品上应在签署前单独展示并要求确认关键摘要：合同主体、服务范围与明确不包含事项、总价及税费/第三方费用、交付物和周期、客户配合义务、退款/解除、责任限制、争议解决、个人信息处理。不能只依赖“我已阅读全部协议”的单一勾选框；免责和重大利益条款应有视觉提示及可回溯的确认记录。

### 1.4 第三方电子签能加强证据链，但仍需自行保存完整证据包

《最高人民法院关于民事诉讼证据的若干规定》第十五条要求电子数据原则上提供原件；第九十三条要求结合系统可靠性、数据完整保存和提取方式等因素判断真实性；第九十四条规定，由记录和保存电子数据的中立第三方平台提供或确认、在正常业务中形成、以档案方式保管或者按当事人约定方式保存的电子数据，可以在无相反证据时确认其真实性。[最高人民法院：《关于民事诉讼证据的若干规定》](https://www.court.gov.cn/zixun/xiangqing/212721.html)

所以“厂商云端有一份”不应是唯一留存策略。每个签完的订单至少要固化：

- 最终双签 PDF/原格式文件及其 SHA-256；
- 订单号、服务代码/修订、价格快照、协议模板 ID/版本和生成文件 ID；
- 双方签署主体、签署完成时间、厂商流程 ID、数字证书/验签结果；
- 实名和意愿认证的结果标识及经脱敏的必要信息，不自行保存人脸原图或视频；
- 厂商签署过程/证据报告、区块链或可信时间戳存证编号（如购买）；
- 回调原始载荷、验签结果、主动查询结果、下载时间和操作审计。

文件应进入私有对象存储并加密，元数据进入 PostgreSQL；公开链接和短期厂商下载 URL 不能作为档案。一般民事权利请求的诉讼时效期间为三年，且可能中止、中断或存在更长保护期间，因此当前“终态满 24 个月清除联系方式”的规则不能直接套用到合同证据包；应由法律与财务负责人按服务期限、争议窗口、会计/税务留存和个人信息最短必要原则制定分层保留期。[最高人民法院发布的《中华人民共和国民法典》，第188条](https://www.court.gov.cn/zixun/xiangqing/233181.html)

## 2. 个人信息合规影响

电子签会新增或扩大处理姓名、手机号、证件类型/号码、企业身份、签署轨迹，某些认证方式还涉及人脸等生物识别信息。《个人信息保护法》第五、六、十七、十九条要求合法、正当、必要、最小范围、事前告知和最短必要保存；第二十一条要求与受托处理方约定目的、期限、方式、数据种类、保护措施和双方权利义务并监督；第二十三条在属于向独立处理者提供信息时要求告知接收方并取得单独同意。[工业和信息化部：《中华人民共和国个人信息保护法》，第5—23条](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)

人脸等生物识别信息属于敏感个人信息，只有目的特定、充分必要并采取严格保护措施时方可处理；通常还要取得单独同意并说明必要性和对个人权益的影响。委托处理、向其他处理者提供信息、处理敏感个人信息均属于应事前进行个人信息保护影响评估并留存记录的情形。[同法第28—30、55—56条](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)

上线前至少完成：

1. 与厂商确认双方是委托处理、独立处理还是分阶段的混合关系，并签数据处理条款；核实存储地域、分包商、删除/导出机制和安全事件通知。
2. 更新隐私说明，在进入厂商页面前显著告知接收方、目的、信息种类、保存期和权利渠道；需要单独同意的场景不要并入服务条款总勾选。
3. 完成个人信息保护影响评估，特别说明为什么需要实名、选择何种意愿认证、是否必须使用人脸，以及是否可提供短信等影响更小的替代方式。
4. Vault2077 只保存厂商账号 ID、认证是否通过、证件尾号等必要结果；完整证件号、人脸照片/视频尽量只在厂商受控页面处理，不进入订单备注、日志、分析工具或错误追踪。
5. 签署 H5、回调和合同下载链路均禁止把姓名、手机号、证件号放入 URL 查询参数、前端日志或公开分析事件。

## 3. 厂商能力核验

### 3.1 e签宝：更适合作为首个技术验证对象

e签宝官方开放平台明确面向开发者提供 API 集成，并覆盖认证、电子签名与区块链存证。[e签宝开放平台介绍](https://open.esign.cn/doc/detail?id=opendoc%2Fhelper%2Fge7uhn&namespace=opendoc%2Fhelper)

与本场景直接相关的官方能力包括：

- **模板和逐单合同**：可通过 `docTemplateId` 填充控件生成 PDF，也可直接上传文件；基于文件发起签署接口支持已上传文件或模板生成文件、签署方、签署区、自动开启/完结、回调地址与签后重定向。[填写模板生成文件](https://open.esign.cn/doc/opendoc/pdf-sign3/mv8a3i)、[基于文件发起签署](https://open.esign.cn/doc/opendoc/pdf-sign3/nxhgcl3bfgqz8qlz)
- **托管签署页**：流程开启后可通过 `POST /v3/sign-flow/{signFlowId}/sign-url` 获取签署/预览链接，支持免登录参数，适合 Vault2077 全页跳转后返回。[获取签署页面链接](https://open.esign.cn/doc/opendoc/pdf-sign3/pvfkwd/)
- **实名与签署意愿**：个人签署需以手机号或邮箱账号标识配合姓名；未实名用户可在签署页实名认证，已实名用户进入签署意愿认证。官方列出的实名方式包括人脸、银行卡四要素、运营商三要素，意愿认证包括短信验证码或人脸等。[用户授权与实名认证](https://open.esign.cn/doc/opendoc/auth3/lmfokx)、[基于文件发起签署的个人签署方参数](https://open.esign.cn/doc/opendoc/pdf-sign3/nxhgcl3bfgqz8qlz)
- **企业盖章**：企业可授权平台自动盖章，或授权经办人每次核身后手动盖章；流程模板还能把自动落章授权限定到具体模板，适合把 Vault2077 电子印章限制在经法律批准的服务协议模板上。[SDK 3.0 对接指南](https://open.esign.cn/doc/opendoc/paas_sdk_3/ox0nhedomdfaycyh)、[流程模板自动落章](https://open.esign.cn/doc/opendoc/helper/si1ih3va3oilpd24)
- **回调与主动查询**：签署事件会推送 JSON 通知，开发者可用通知请求头验签；长时间未收到回调时官方建议主动查询流程。流程结束通知区分完成、撤销、过期和拒签。[签署回调通知接收说明](https://open.esign.cn/doc/opendoc/notify3/sblzg8)、[签署流程结束通知](https://open.esign.cn/doc/opendoc/notify3/glqgy1)、[查询签署流程详情](https://open.esign.cn/doc/opendoc/pdf-sign3/xxk4q6)
- **下载、验签和出证**：完成状态可申请签后文件下载地址；平台提供文件签名有效性核验、流程存证核验和证据报告/区块链全流程报告申请。[下载已签署文件](https://open.esign.cn/doc/opendoc/pdf-sign3/kczf8g)、[核验合同文件签名有效性](https://open.esign.cn/doc/opendoc/pdf-sign3/yekrnc)、[存出证产品说明](https://open.esign.cn/doc/opendoc/helper/wukdssaps0fio55u)
- **公开价格**：官方价格页当前列出的“公有云 SaaS API 标准版”为按签署合同份数一次性付费，标价 8 元/份，并列有企业签、个人签、法定代表人签和个人/组织实名认证；非标版按合同份数、认证方式/次数、存证等分别计费并需报价。实际是否含自动落章、短信、证据报告、存储和最低采购量必须以商务合同为准。[e签宝开放平台价格页](https://open.esign.cn/h5/price)

### 3.2 腾讯电子签：微信生态优先时的备选

腾讯电子签官方 API 说明支持使用文件或模板创建合同、企业静默签署、手动签署、回调，并提供 PHP、Python、Java、Go、C# 示例；其产品说明称提供实名认证、区块链存证与证据保全。[腾讯云：电子签 API 简介](https://cloud.tencent.com/document/api/1323/70377)

用户签署可以走两条路：`CreateUserAutoSignEnableUrl` 等具体能力需按场景核实，面向个人的通用做法是获取 H5 签署链接，支持 App、支付宝或浏览器直接打开；也可生成跳转腾讯电子签小程序的链接/二维码，适合 PC 扫码或微信场景。[获取 H5 签署链接](https://cloud.tencent.com/document/api/1323/85818)、[获取小程序签署链接](https://cloud.tencent.com/document/api/1323/70359)。企业运营页面还支持 iframe 可嵌入 Web URL，但这不等同于所有自然人签署流程都适合 iframe。[可嵌入页面接口](https://cloud.tencent.com/document/product/1323/95589)

商业门槛需要特别注意：官方文档称 API 接入仅支持专业版或旗舰版；购买指南又把“第三方应用集成”列为专业版/旗舰版可购买的增值服务。旗舰版需联系销售报价，公开页面价格可能随选购页动态变化。[API 简介的版本限制](https://cloud.tencent.com/document/api/1323/70377)、[购买指南](https://cloud.tencent.com/document/product/1323/53795/)、[定价常见问题](https://cloud.tencent.com/document/faq/1323/71859)

### 3.3 选型建议

| 维度 | e签宝 | 腾讯电子签 | 对本项目的判断 |
|---|---|---|---|
| 无账号 Web 用户 | H5 签署链接、免登录选项与重定向文档清晰 | H5 浏览器/支付宝与小程序跳转均可 | 首版 e签宝路径更直接 |
| 模板与自动盖章 | 文件/流程模板、模板限定自动落章 | 文件/模板、企业静默签署 | 均可，必须限制印章授权范围 |
| 回调与补偿 | 回调验签 + 主动查询文档明确 | 有回调配置和状态查询能力 | 均需实现“回调 + 查询”双保险 |
| 证据 | 下载、验签、存证、出证接口较完整 | 区块链存证与证据保全能力 | 以实际套餐和样例报告验收 |
| 公开价格 | 标准 API 版 8 元/份；非标询价 | API 需专业/旗舰 + 集成增值项，最终看购买页/报价 | 低量试点先拿两家正式报价 |
| 生态 | 通用 Web/API | 微信、小程序、企业微信优势明显 | 若订单入口未来迁移微信，再重评腾讯 |

建议先用 e签宝沙箱做一条完整 happy path 和三条失败 path，再拿腾讯电子签做商务与数据条款对照；不要同时开发两个生产适配器。

## 4. 推荐产品流程与接口编排

### 4.1 用户流程

1. 用户在公开服务详情确认名称、范围、修订快照和价格，进入统一下单页。
2. 选择签约主体类型：自然人，或企业/个体工商户；首版若只支持自然人必须明确限制，不能让企业经办人误以个人身份替公司签约。
3. 填写签约姓名和可完成认证的手机号；企业签约还需企业名称、统一社会信用代码及经办人身份/权限。情况说明继续禁止录入证件和业务材料。
4. 阅读合同摘要、重大条款提示和隐私告知，分别完成必要确认。
5. Vault2077 创建 `awaiting_signature` 订单申请，绑定服务/价格快照和高熵恢复令牌，不生成付款链接。
6. 服务器填充批准的合同模板，发起双方签署流程，取得厂商 H5 链接；浏览器全页跳转至厂商完成实名、意愿认证和签署。
7. Vault2077 企业电子印章只对该批准模板和本订单生成的最终文件自动落章。不得对空白文件、任意上传文件或用户可编辑正文开放静默盖章。
8. 厂商回调只作为“状态可能变化”的信号；服务器验签后仍主动查询并确认“整个流程完成”，再下载最终文件、验签、计算哈希、归档证据包，将订单更新为 `awaiting_payment`。
9. 用户被重定向回同源恢复页面。恢复页面只凭高熵、限时、可撤销令牌查询；服务器若尚未确认回调则主动查厂商或短轮询。确认双签完成后才生成支付宝付款链接并跳转。
10. 支付到账仍只信任支付宝验签服务器通知或后台主动查询；签署完成的浏览器返回页不能改变合同状态，付款返回页也不能改变到账状态。

### 4.2 建议状态机

```text
awaiting_signature
  ├─(双方签署完成 + 服务器复查)→ awaiting_payment
  ├─(拒签)→ signature_rejected
  ├─(过期)→ signature_expired
  └─(主动取消)→ cancelled

awaiting_payment
  ├─(支付服务确认到账)→ paid → completed → refunded
  └─(支付超时/取消)→ cancelled
```

不要继续用一个 `awaiting_payment` 同时代表“未签”和“已签未付”。支付通知处理函数还应增加硬门禁：订单合同状态不是已完成时，即使收到意外支付通知也不得静默进入正常交付，必须进入人工异常处置并保留交易事实。

### 4.3 服务端模块

- `esign-provider` 适配器：鉴权、模板填充、发起流程、获取签署链接、查询状态、下载文件、验签/出证；业务层不散落厂商字段。
- 创建签约请求 API：复用当前同源检查、限流和幂等键，但返回签署链接而不是付款链接。
- 厂商回调 API：原始请求体验签、时间戳/重放校验、幂等事件表、流程 ID 与订单绑定校验；收到通知后再查询厂商确认状态。
- 无账号恢复 API：高熵令牌只允许查看本人订单的最少状态并在已签后生成付款链接；令牌哈希入库，设置有效期和轮换，不能只凭可猜测的订单号。
- 证据归档 worker：异步下载最终 PDF、计算哈希、保存私有 OSS、记录下载和验签结果；失败重试并报警。首版可以由回调触发，但不能让长时间下载阻塞回调响应。
- 后台：显示签署状态、签约双方、模板版本、厂商流程 ID、归档/验签状态；允许重新发起已过期流程、下载证据包和查看审计，不允许人工把未签订单直接改为已签。
- 生产配置门禁：厂商生产 App/密钥、企业认证、印章与模板授权、回调公钥/密钥、回调公开地址、私有存储、正式套餐、协议版本均有效，否则下单入口保持关闭。

## 6. 难点、风险与处理方式

| 风险 | 为什么重要 | 建议控制 |
|---|---|---|
| 签约主体不清 | “Vault2077”是品牌名，不一定是可签约法律主体；客户也可能是自然人或公司 | 协议、收款商户、发票和实际服务提供者主体一致；前台明确展示全称和统一社会信用代码 |
| 经办人无权代表企业 | 实名只能证明“是谁”，不自动证明“有权代表哪家公司” | 企业认证、成员/经办人授权和企业电子印章链路单独验证；保存授权证据 |
| 自动盖章被滥用 | 开放平台静默盖章相当于高权限签章能力 | 印章授权限定批准模板；动态字段白名单；金额/订单/服务快照服务端填充；双人审批变更模板；密钥放密钥管理系统 |
| 浏览器返回被伪造 | 用户可以手工访问 return URL | 返回页只触发服务器查询；状态只由验签回调或主动查询改变 |
| 回调丢失、重复、乱序 | 第三方通知不是恰好一次 | 事件幂等、状态单向转换、主动查询补偿、定时扫描卡单 |
| 首次实名导致流失 | 用户可能需要证件、短信或刷脸；PC 可能先扫签署码再扫付款码 | 手机号作为首版必填；优先影响较小的可用认证；在按钮前说明步骤和耗时；移动端 H5 优先 |
| iframe/CSP/摄像头兼容 | 跨域身份认证可能受浏览器、`frame-src`、摄像头权限和小程序限制 | 首版全页跳转；仅在厂商明确支持并完成多端兼容测试后再 iframe |
| 厂商依赖与调证成本 | 套餐到期、接口变化或争议发生时可能无法即时取证 | 签后立即自持最终文件、哈希和证据元数据；定期抽样验签；合同约定导出、删除、SLA 和退出机制 |
| 现有 24 个月清理规则冲突 | 联系方式最小化与合同举证窗口需要平衡 | 联系方式、身份认证结果、合同正文、财税凭证分别定期限；由法律/财务/隐私负责人共同批准 |

## 7. 工作量拆分与验收

### 阶段 A：业务与供应商准备（约 3—7 个工作日，不含厂商审核等待）

- 确定实际签约/收款/开票主体和自然人、企业客户支持范围；
- 完成一份标准服务协议母版及重大条款摘要；
- 获取两家正式报价、数据处理条款、SLA、证据报告样例和退出/导出说明；
- 完成企业认证、电子印章和模板限定自动落章授权；
- 完成个人信息保护影响评估初稿。

### 阶段 B：沙箱技术验证（约 3—5 个工作日）

- 一份固定模板、一个测试服务、自然人签署；
- 验证首次实名、再次签署、拒签、过期、回调丢失后的主动查询；
- 验证双签 PDF 下载、离线验签/厂商验签、哈希稳定性和证据报告；
- 在 iOS/Android 微信内浏览器、系统浏览器、支付宝内浏览器和桌面端测试完整返回链路。

### 阶段 C：生产 MVP（约 2—4 周）

- 状态机和数据迁移、厂商适配器、回调、恢复令牌、证据 worker；
- 前台合同摘要与签署/付款两阶段体验；
- 后台合同状态、下载、重试和审计；
- 生产配置门禁、监控报警、隐私文案和运维手册；
- E2E 覆盖“未签绝不出付款链接”“伪造返回不改变状态”“重复/乱序回调幂等”“签完后支付宝金额仍绑定原订单快照”。

若首版同时支持企业客户，应额外预留 2—4 周处理组织认证、经办人授权、企业名称/统一社会信用代码校验、企业签署失败恢复及发票抬头一致性。

## 8. 推荐决策

建议**做，但分两步批准**：

1. 先批准一个不触及生产订单的 e签宝沙箱 PoC，只验证一份合同从模板生成、自然人签署、Vault2077 自动盖章、回调查询、文件归档到离线验签的闭环；同时向腾讯电子签索取同口径正式报价。
2. PoC 通过后再修改 ADR 0014、OPC 规格、系统交付规格、上线清单和订单状态机。调研文档本身不构成需求，不能直接据此改生产代码。

生产立项前必须由业务负责人回答四个问题：

- 实际服务提供、收款、开票和盖章的法律主体是哪一个？
- 首版客户只允许自然人签，还是必须支持企业/个体工商户作为合同一方？
- 服务合同是双方签完成立、付款后生效，还是另有约定？
- 哪些合同、身份结果和证据材料分别保存多久，用户如何下载其合同？

如果这些答案未确定，继续开发 API 只会把法律和数据模型的不确定性固化进代码。

## 9. e签宝接入责任边界与实际操作清单

推荐使用 e签宝 SaaS API V3 的“流程模板 + 托管 H5”路径：在流程模板中固定协议正文、参与方角色、签署位置和本企业自动落章范围；Vault2077 服务器按订单填充受控字段并创建签署流程，再调用 `POST /v3/sign-flow/{signFlowId}/sign-url` 获取免登录签署页。签署完成通知只作为状态变化信号，服务器验签回调并主动查询流程，下载、验签和归档最终文件后，才开放支付宝付款链接。[e签宝 SaaS API V3 开发者指南](https://open.esign.cn/doc/opendoc/dev-guide3/lbva7leuuze3zwt9)、[获取签署页面链接](https://open.esign.cn/doc/opendoc/pdf-sign3/pvfkwd)、[签署回调通知接收说明](https://open.esign.cn/doc/opendoc/notify3/sblzg8)

如果正式 AppID 的所属主体与 Vault2077 的签约、收款、开票和盖章主体是同一家公司，应使用本企业印章和模板范围内的自动落章授权，不应引入跨企业印章授权。自动落章授权必须由企业管理员或法定代表人签署授权书、完成意愿认证，并限制到批准的流程模板；这是高权限法律行为，不能由代码或开发者代替。[流程模板如何自动落章](https://open.esign.cn/doc/opendoc/helper/si1ih3va3oilpd24)、[印章开放服务介绍](https://open.esign.cn/doc/opendoc/seal-open-api/intro)

### 必须由企业管理员、法定代表人或业务负责人完成

1. 以真实运营主体注册 e签宝企业开发者账号并完成企业实名认证；企业管理员需先完成个人账号注册和实名认证。[企业开发者账号注册及实名认证流程](https://open.esign.cn/doc/opendoc/helper/ogfnv9)
2. 与 e签宝签订商务合同、购买套餐并由企业管理员设置套餐生效时间；套餐生效权限不能交给开发代码。[如何生效订购的套餐](https://open.esign.cn/doc/opendoc/helper/xw5hlihdd1zdrzx9)
3. 批准最终服务协议、重大条款摘要、动态字段白名单、签章位置和合同成立/生效时点。
4. 创建或确认本企业电子印章，由企业管理员或法定代表人签署印章授权书并完成意愿认证；自动落章权限只绑定批准的流程模板。
5. 批准生产应用、回调域名、服务器出口 IP 白名单和正式上线时间；e签宝建议上线前 2—3 天向交付顾问报备。[接口集成调用说明](https://open.esign.cn/doc/opendoc/paas_sdk_3/syiyud75beynh1gs)
6. 把生产 AppID、AppSecret、模板 ID、机构 ID、印章 ID 通过本地 `.env.local`、systemd `EnvironmentFile` 或部署 Secret 安全注入；不得在聊天、Git、工单正文或浏览器日志中发送 AppSecret。

### Codex 可以独立完成的工程工作

1. e签宝服务端适配器、HmacSHA256 请求签名、超时、错误码兼容和沙箱/生产配置隔离；e签宝官方优先推荐请求签名鉴权。[请求签名鉴权方式说明](https://open.esign.cn/doc/opendoc/dev-guide3/tggw2e)
2. 订单 `awaiting_signature → awaiting_payment` 状态机、幂等、恢复令牌和“未签不得生成付款链接”的服务器硬门禁。
3. 流程模板变量映射、签署流程创建、免登录 H5 跳转、返回页、轮询和主动状态查询。
4. 回调原始请求体验签、时间戳和重放防护、重复/乱序事件幂等及丢失回调补偿。
5. 最终 PDF 下载、验签、SHA-256、私有 OSS 归档、后台状态与监控告警。
6. 自动化测试、沙箱端到端联调、生产配置门禁和上线运行手册。

沙箱和生产环境的数据物理隔离；沙箱合同不具法律效力，生产 AppID、模板、印章和相关 ID 必须在正式环境重新创建和配置，不能直接复用沙箱值。[e签宝公有云 API 调用说明](https://open.esign.cn/doc/opendoc/dev-guide3/el34xh)

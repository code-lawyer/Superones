# PayAI.Plus 接入 Vault2077 可行性调研（2026-08-18）

## 1. 结论

**当前不应把 `payai.plus` 接入 Vault2077。** 这不是“技术工作量较大但可以开始开发”，而是公开证据尚不足以建立可实施的供应商与安全合同：

1. `payai.plus` 公开定位是面向终端消费者销售 ChatGPT、Claude 会员充值卡密的独立第三方零售平台，不是供其他商户收款、分销或代发卡密的支付服务商。[关于我们](https://payai.plus/about)、[服务条款](https://payai.plus/terms)（核验：2026-08-18）
2. 官网没有公开商户入驻、渠道合作、SDK、API、Webhook、状态枚举、鉴权、幂等、对账、结算、费率或 SLA 文档；也没有从官网链接到可确认属于该站的源码仓库。公开零售网页中存在内部支付回调和订单查询，不等于向第三方开放的稳定接口。[订单查询](https://payai.plus/order)、[隐私政策](https://payai.plus/privacy)（核验：2026-08-18）
3. 官网没有公开经营主体全称、统一社会信用代码、注册地址、收款主体、许可/备案编号或签约实体。其“可开正规企业发票”表述只能证明平台作出该项销售承诺，不能替代供应商 KYC、合同主体和资金结算核验。[关于我们](https://payai.plus/about)、[联系我们](https://payai.plus/contact)（核验：2026-08-18）
4. 更严重的是，官方充值教程要求用户复制完整 `AuthSession` JSON 并粘贴到充值页面，且明确说明 Session 相当于临时登录凭证。[充值教程](https://payai.plus/guide)（核验：2026-08-18） 这会把第三方 AI 账户接管级凭证引入交易链路；公开隐私政策只列出邮箱、订单、支付、卡密、客服材料和基础日志，没有说明该 Session 的接收主体、字段范围、传输、保存、使用、删除、分包商或安全事件响应。[隐私政策](https://payai.plus/privacy)（核验：2026-08-18）
5. Vault2077 已通过 [ADR-0022](../adr/0022-retire-online-payment-integration.md) 退役在线支付运行能力，新订单只允许 [ADR-0020](../adr/0020-opc-offline-bank-transfer-checkout.md) 的线下对公转账。即使 PayAI.Plus 未来提供合格接口，恢复在线支付或增加新的外部数字商品链路也必须先提出新 ADR，不能在当前实现上直接接入。

因此，当前建议是 **No-Go**：不调用其未公开接口、不把它包装成 Vault2077 支付通道、不代收或中转用户 Session、不在 OPC 目录上架其卡密，也不把普通外链描述为“已接入”。只有对方补齐正式 B2B/渠道合同、经营主体与上游授权、接口与安全文档，并移除 Session 凭证提交链路后，才值得重新评估。

## 3. 它实际是什么

PayAI.Plus 自称面向国内用户的独立第三方 AI 会员充值服务平台，销售 ChatGPT、Claude 等数字商品，提供人民币支付、卡密交付、充值指引、订单查询和售后；它同时明确声明自己不是 OpenAI、Anthropic 或相关产品的官方网站、关联公司或授权代理。[关于我们](https://payai.plus/about)、[服务条款](https://payai.plus/terms)（核验：2026-08-18）

公开的消费者流程是：

```text
选择固定商品
  -> 填写邮箱
  -> 微信扫码支付人民币
  -> 页面与邮件交付一次性卡密
  -> 在充值页面验证卡密
  -> 登录目标 AI 账号并取得完整 AuthSession JSON
  -> 把 Session 粘贴回充值页面
  -> 等待会员状态更新
```

商品页和条款说明支付成功后自动发放卡密；订单可用订单号或邮箱查询；未支付订单可能过期；支付、库存或回调异常可能进入补发、协助或退款。[ChatGPT 商品页](https://payai.plus/chatgpt)、[订单查询](https://payai.plus/order)、[服务条款](https://payai.plus/terms)、[充值教程](https://payai.plus/guide)（核验：2026-08-18）

这是一条 **PayAI.Plus 自营商品的托管零售链路**。它没有公开表示可以：

- 代表 Vault2077 向 Vault2077 用户收款；
- 把款项结算给 Vault2077；
- 让 Vault2077 创建、查询或退款订单；
- 让 Vault2077 批量采购、分销或白标发卡；
- 向 Vault2077 发送签名 Webhook；
- 允许 Vault2077 复制、镜像或调用其内部页面接口。

相反，服务条款禁止未经许可复制、镜像、抓取其页面、文案、设计和系统功能或用于商业用途。[服务条款](https://payai.plus/terms)（核验：2026-08-18） 因此，逆向网页私有接口既不是正式接入，也缺少合同与版本稳定性。

## 5. 安全与合规硬阻断

### 5.1 Session 不是“无需账号凭证”

官网多处强调不要求账号密码，但教程的实际步骤是：用户登录 ChatGPT/Claude，打开 `AuthSession` 页面，复制完整 JSON，再粘贴到充值页面；官网自己将其定义为临时登录凭证。[充值教程](https://payai.plus/guide)（核验：2026-08-18）

因此，“不收密码”不能被解释为“不接触账户凭证”。对 Vault2077 而言，任何下列实现都不可接受：

- 在 Vault2077 页面收集并转发 Session；
- 把 Session 写入 PostgreSQL、日志、审计、队列、邮件、客服截图或第三方分析；
- 让 Vault2077 管理员或生产账户使用该充值链路；
- 通过前端直传来规避 Vault2077 自己“不存储”的责任判断；
- 以卡密或一次性为由降低账户接管级凭证的安全等级。

OpenAI 的个人使用条款也明确禁止分享账户凭据或让他人使用账户。[OpenAI 使用条款](https://openai.com/zh-Hans-CN/policies/terms-of-use/)（核验：2026-08-18） 本报告不对 PayAI.Plus 的具体链路作法律定性，但 Vault2077 没有证据证明将完整 Session 提交给第三方获得了上游授权。

### 5.2 主体和上游货源不可验证

官网没有披露可供合同核验的运营企业，且明确否认自己是 OpenAI/Anthropic 授权代理。其条款又说明价格、库存和“上游资源”会波动。[服务条款](https://payai.plus/terms)（核验：2026-08-18） 在取得以下证据前，Vault2077 无法确认卡密来源、订阅采购权、退款追索对象、发票主体与实际收款主体是否一致。

### 5.3 中国大陆可支付不等于上游可用

PayAI.Plus 的页面、人民币价格和微信支付面向国内用户，但上游官方地区政策是独立门槛。OpenAI 的当前支持列表没有中国大陆，并说明在列表外访问或提供访问可能导致封禁/暂停；Anthropic 更明确限制来自中国的使用与销售。[OpenAI 支持地区](https://help.openai.com/zh-hans-cn/articles/7947663-)、[Anthropic 地区限制公告](https://www.anthropic.com/news/updating-restrictions-of-sales-to-unsupported-regions)（核验：2026-08-18）

因此，Vault2077 若把这类商品作为自己的公开服务，会同时承担上游资格、持续交付、用户误解和售后争议风险；PayAI.Plus 条款把相当一部分账号/地区/风控后果留给用户，不能满足 Vault2077 对标准服务“可检查交付与验收”的要求。

## 6. 与 Vault2077 的适配判断

### 6.1 作为 OPC 付款通道：不可行

PayAI.Plus 不提供替 Vault2077 收款和结算的公开产品。它不能替代现行公司同名对公账户，也没有商户 API/Webhook/对账/退款证据可接入。更重要的是，Vault2077 当前 [ADR-0022](../adr/0022-retire-online-payment-integration.md) 已删除在线支付 SDK、回调、查询、关单、退款和密钥；直接新增任何在线通道都违背已接受决策。

### 6.2 作为 Vault2077 自营标准服务的上游：当前不可行

若 Vault2077 先向用户收费，再向 PayAI.Plus 采购或发放卡密，Vault2077 会成为面向用户的履约与售后责任方，但目前没有批发合同、库存 API、自动发卡、价格锁定、对账、退款、商标使用、上游授权、数据处理或 SLA。消费者网页不能承担供应链合同。

同时，用户必须提交目标 AI 账户的 Session。把这一动作嵌入 Vault2077 会与当前无账号公开产品的最小凭证边界相冲突，并额外引入高价值第三方账户凭证。

### 6.3 作为游骑兵/外部服务外链：技术上可放链接，当前仍不建议

普通 HTTPS 外链不需要 SDK，但这只是导流，不是服务接入。若页面呈现不足以清楚区分责任主体，用户会合理误解 Vault2077 对支付、卡密来源、Session 安全、充值结果和退款提供背书。至少需要完成主体核验、明确合作/非合作关系、品牌授权、商业披露和风险说明；当前官方材料不支持这些前提。

### 6.4 作为 Vault2077 内部采购：只能视为人工零售采购，不是集成

理论上可由个人自行购买公开商品，但不应使用 Vault2077 管理员、生产邮箱、代码托管、云平台或其他高权限账户，也不应由 Vault2077 代持 Session。考虑上游地区政策和 Session 风险，本报告同样不推荐把它作为团队标准采购渠道。

## 7. 如要重新评估，对方必须先提供的材料

以下材料应由可核验的签约主体通过正式渠道提供；客服聊天截图或网页口头承诺不足以通过生产门禁：

1. 营业执照、统一社会信用代码、注册地址、实际控制/联系人、合同与开票主体，以及微信收款商户主体的一致性证明。
2. OpenAI、Anthropic 或合法上游分销方允许采购、转售、代充、使用商标并向中国大陆用户交付的书面授权与适用地区。
3. 正式渠道/商户合同：商品范围、库存、价格锁定、税费、最低量、保证金、结算、发票、退款、拒付、终止和存量订单处理。
4. 公开或合同附件形式的 API 规范：生产/沙箱地址、版本、鉴权、最小权限、IP/证书约束、请求签名、幂等键、速率限制、错误码和弃用期。
5. Webhook 合同：事件状态、签名、时间窗、防重放、重试、乱序、重复、终态、回放和主动查询兜底。
6. 对账与资金证据：订单号映射、支付/退款交易号、日账单、差错处理、结算账户与资金隔离说明。
7. 明确且不再要求用户提交完整账号 Session 的交付方案；若仍处理任何上游授权令牌，需要字段级数据流图、用途、保存时长、删除证明、子处理者与安全审计。
8. 数据处理协议：个人信息角色、处理目的、数据位置、跨境路径、保留期、用户权利、安全事件通知时限和退出迁移。
9. SLA 与运营证据：可用性、P95 延迟、发卡时限、RTO/RPO、状态页、事件响应、漏洞披露、渗透测试或独立审计。
10. 面向 Vault2077 的真实沙箱与小额闭环：创建、支付、重复通知、主动查询、发卡、过期、退款、异常恢复和对账全部通过，且不使用生产客户或高权限账户。

即使材料齐全，Vault2077 仍需先提出新 ADR，明确是在增加“在线支付提供方”“数字商品上游”还是“外部独立服务导流”；三者的责任、状态机、数据和审计边界不同，不能用一个模糊的“接入 PayAI”实现覆盖。

## 8. 同名排除：`payai.plus` 不等于 PayAI Network

搜索时还会出现 `payai.network` 及 `PayAINetwork` GitHub 组织，其产品是面向 AI/API 的 x402/MPP 机器支付 facilitator 和开源 SDK，涉及 USDC、多条 EVM/Solana 网络及 HTTP `402 Payment Required`。[PayAI Network 官网](https://payai.network/)、[PayAI Network 文档](https://docs.payai.network/introduction)、[PayAINetwork GitHub](https://github.com/PayAINetwork)（核验：2026-08-18）

`payai.plus` 官网没有链接或声明与该组织存在关系，其产品、域名、支付资产和用户流程完全不同。本报告不把 PayAI Network 的 SDK、API、链、许可证或成熟度归给 PayAI.Plus；如果未来要评估 x402，应另开独立调研。

## 10. 最终建议

维持 **No-Go**。当前最合理的动作不是编写适配器，而是把 PayAI.Plus 视为一个尚未通过供应商、安全和上游授权尽调的消费者零售站。如果业务目标是给 OPC 增加在线收款，应另选具备明确企业商户入网、官方 API、签名通知、主动查单、原路退款和公司同名结算的持牌支付/收单产品；如果目标是提供 AI 会员采购服务，则应先确认上游地区与转售授权，并采用不接触用户 Session 的正式企业采购渠道。

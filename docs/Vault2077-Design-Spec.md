# Vault2077 总设计规格

## 1. 产品定义

Vault2077 是面向超级个体与一人公司的公开网站。它把四类长期需求放在同一套低噪声界面中：

1. Vault 信息流：把公开资讯沉淀为可追溯事件。
2. OPC 服务台：提供标准化经营服务，并展示独立顾问名录。
3. SiC 学院：阅读正式技术来源，并查看平台原生榜。
4. 边境计划：以公开仓库参加无需账户的季度竞赛。

公开用户无需创建 Vault2077 账户。运营人员通过独立管理来源和强身份认证进入后台处理真实输入和异常；生产后台不是公开产品账户体系的一部分。

## 2. 权威边界

本文件定义四频道共享的产品目标、导航、公开边界和视觉原则。频道内部规则分别以信息流、OPC、SiC、边境计划专项规格为准；工程边界以系统交付规格和已接受 ADR 为准。

产品页面不得向公开用户披露服务器位置、跨区域拓扑、模型名称、内部阈值、来源抓取错误或运行密钥。`/pipeline` 是本地/后台诊断入口，不是公开产品频道。

## 3. 信息架构

### 3.1 一级导航

固定一级入口：

- `/`：总览
- `/feed`：Vault 信息流
- `/opc`：OPC 服务台
- `/sic`：SiC 学院
- `/frontier`：边境计划

管理和诊断入口不进入公开主导航。边境计划的往届结果在频道内呈现，不增设独立 `/frontier/archive` 产品页。

### 3.2 首页

首页承担导航而非复制四个频道：

- 首屏用一句主张和四个入口说明网站能解决什么；
- Vault 预览展示近期事件及证据数量；
- OPC 预览分别指向基础设施、专项服务、游骑兵协会；
- SiC 预览展示最新内容与平台原生榜入口，不显示自算增长；
- 边境计划预览展示当前赛季、当前排名和参加入口。

任何预览数据不可伪装成实时事实；降级或样例状态必须清楚标注。

## 4. 频道合同

### 4.1 Vault 信息流

- 默认视图为事件簿，同时提供资讯瀑布。
- 资讯瀑布只收新闻型材料；机构深度研究与技术材料进入 SiC 档案，不双重发布。
- Hacker News 与 Lobsters 作为社区条目的一手来源进入路边社，外链只展示、不递归抓取。
- 事件必须能回到组成资讯和原始来源。
- 综合摘要以中文呈现并通过编号关联证据。
- 公开页面只呈现内容、来源和更新时间，不呈现采集与处理拓扑。

详细规则见 [信息流设计规格](Vault2077-Feed-Design-Spec.md)。

### 4.2 OPC 服务台

OPC 只有三个一级入口：

- 基础设施：以七项首版 SKU 初始化、可经受控后台修订的跨领域标准交付。
- 专项服务：以十四项首版 SKU 初始化，按六个专业领域组织的单项标准交付。
- 游骑兵协会：按十类顾问身份展示外部独立顾问。

基础设施和专项服务由 Vault2077 直接交付。用户在具体服务详情登记最小联系方式后形成待付款订单，并跳转支付宝官方收银台；支付宝验签通知自动更新到账状态，后台交易查询用于异常补查。浏览器返回页面不能被表述为到账证明。游骑兵由用户直接联系，Vault2077 不参与后续定价、付款、交付或争议。

OPC 标语为“超级个体，全栈运行”。只有 OPC 面向用户的服务目录正文允许后台人工编辑；资讯、来源事实、SiC 平台榜和 Frontier 排名继续由自动管线产生，不进入人工内容管理。

详细规则见 [OPC 设计规格](Vault2077-OPC-Design-Spec.md)。

### 4.3 SiC 学院

SiC 包含论文、档案、课程、播客四个内容组，以及以下平台原生榜：

其中档案只收机构深度研究与技术材料，不收新闻稿、例行 Release Notes 或 Changelog，也不与 Vault 资讯瀑布重复。

- GitHub Trending：Today、This week、This month。
- Hugging Face：Trending。
- OpenRouter：`top-weekly`。
- skills.sh：All Time、Trending 24h、Hot。

不设置 MCP 榜，不从历史快照计算 GitHub、Hugging Face 或 skills.sh 的增量，不把榜单解释为质量、安全、能力或投资评级。

详细规则见 [SiC 设计规格](Vault2077-SiC-Design-Spec.md)与[来源目录](Vault2077-SiC-Source-Catalog.md)。

### 4.4 边境计划

- 公开用户以仓库地址和私人联系邮箱提交。
- 网站由境内服务端优先即时核验公开仓库；GitHub 暂时不可达时保持待验证并转入只含公开仓库标识的异步任务。邮箱不进入 GitHub 请求或境外公开任务。
- 排名只使用赛季净增 Star；无评委分与人工推荐。
- 每个自然季度结算冠军和随机奖池。
- 公开展示仓库，不公开私人邮箱或后台状态。

详细规则见 [边境计划设计规格](Vault2077-Frontier-Design-Spec.md)。

## 5. 共享交互

### 5.1 频道编辑一致性

- information、roadside 及其形成的事件统一使用 Vault 编辑配置，保持标题、摘要、证据措辞与事件归属语义一致。
- SiC 使用独立 SiC 编辑配置，强调术语忠实、方法与局限，不把研究材料改写成新闻语气。
- 频道之间可以有明确不同的声音，但事实、来源、统一语言、原始字段和可追溯标准不得分叉。
- 平台原生榜和 Frontier 的仓库核验、Star 观察、排名与结算都是确定性数据处理，不得使用编辑模型生成或修改结果。
- 公开页面不展示处理提供方、模型名称、提示版本、备用切换或队列状态。

### 5.2 状态

每个依赖远程或异步数据的区域都必须有：

- 首次加载状态；
- 空状态；
- 可恢复错误状态；
- 最近成功更新时间；
- 数据过期提示；
- 表单防重复提交与提交结果。

不能用空白区域、无限加载或静默回退隐藏失败。

### 5.3 链接与证据

- 原始来源使用清楚的外链标识。
- 外链失败不应破坏当前页面。
- 摘要、榜单和排名不得伪装为平台官方背书。
- 时间必须说明时区或使用用户可理解的相对时间。

### 5.4 无障碍与键盘

- 所有功能可由键盘完成；
- 焦点可见且顺序符合阅读顺序；
- 表单错误与字段关联；
- 颜色不是唯一状态信号；
- 动效遵循 `prefers-reduced-motion`。

## 6. 响应式与视觉

标准验收宽度为 `360 / 768 / 1280 / 1440` 像素；`320` 可作为额外压力测试，但不替代标准宽度。

视觉基调是高密度但低噪声的编辑部/档案馆：

- 用排版层级、留白和细线建立秩序；
- 避免把所有内容做成等权卡片；
- 重点颜色只表达交互、状态或频道身份；
- 移动端保持阅读与主要操作完整，不仅是缩小桌面布局；
- 页面不因真实标题、来源名或数字长度产生横向溢出。

## 7. 数据与隐私

- 公开内容与公开仓库元数据可以跨区域采集。
- 私人邮箱、运营资料、后台会话和业务写模型留在境内系统。
- 正式启用内容频道前必须建立真实、可追溯的上线基线；页面不得用代码内样例或伪造实时内容填补空白。
- SiC 上线基线按 approved 来源至少保留最近一条符合准入边界的内容，不受日常增量窗口限制；Vault 上线基线仍受新闻时效与事件晋升规则约束，不按来源强行填入陈旧资讯。
- 上线基线与后续增量使用相同稳定 ID、去重、编辑配置、Schema 和发布流程，并分别展示原始发布时间与最近成功采集/发布时间。
- 预览环境可使用单写者文件适配器；真实注册、自动发布和赛季结算前必须使用 PostgreSQL。
- Redis 与对象存储不是生产首版的强制依赖。
- 公开页面不暴露密钥、内部提示词、错误堆栈、原始采集包或后台诊断。

## 8. 发布边界

“页面可浏览”不等于“可生产上线”。发布结论以[上线清单](Vault2077-Launch-Checklist.md)为门禁，以[实现追踪矩阵](Vault2077-Implementation-Traceability.md)记录证据。任何未完成的生产门禁必须显式保留为阻断项，不得通过修改文案伪装完成。

# Vault2077 SiC 学院设计规格

## 1. 目标

SiC 学院帮助超级个体持续阅读硅碳共生相关的一手正式内容，并观察主流技术平台公开定义的热度与采用视图。它不是新闻流、课程商城、项目推荐器或质量评分系统。

## 2. 页面结构

`/sic` 由两部分组成：

1. 最新内容：论文、档案、课程、播客。
2. 平台原生榜：GitHub、Hugging Face、OpenRouter。

公开页面使用一条连续滚动轴聚合论文、平台原生榜、档案、课程和播客。首段以当周首篇论文和分批论文目录建立阅读入口；平台榜以全宽章节带嵌入阅读途中；档案、课程和播客在同一页面继续排列。页面不得在文字缎带下增加栏目导航，也不得要求用户切换独立界面才能获得完整上下文。

公开页面一次读取当前 SiC 内容快照与平台榜快照，但不同内容组和不同平台仍保持各自的来源、字段、顺序、状态和降级语义，绝不合成综合排名。栏目使用稳定 hash 地址：`sic-papers`、`sic-rankings`、`sic-group-documents`、`sic-group-courses`、`sic-group-podcasts`；榜单平台使用 `board=<board-id>` 查询状态。历史 `view` 查询链接继续渲染完整聚合页，并依靠原有 hash 定位，不再触发界面切换。

## 3. 内容组

### 3.1 论文

论文组以 Hugging Face 官方 Papers API 的当前 ISO 周清单为唯一发现入口，通过 `week=YYYY-Www` 分页拉取整周条目和 `paper.upvotes`，不抓取网页。系统按 upvotes 在本地生成周排名；标题、日期、摘要与原始链接由 arXiv API 核验，再由 `sic_editorial` 生成中文编辑字段。页面显示该周多篇论文，而不是按来源压缩为一篇。

### 3.2 档案

只接入机构自营的深度研究、技术报告、系统卡、方法论与长篇工程材料。新闻稿、公司公告、营销活动、例行 Release Notes 与 Changelog 不属于档案；其中新闻型内容进入 Vault 资讯瀑布，深度材料不得在那里重复发布。不得把个人解读或二次复现冒充官方档案。

宽泛混合 Feed 只有在能通过固定栏目、路径或专用入口稳定排除新闻与营销内容时才可批准；不得让境内 LLM 承担逐篇决定“进资讯还是进档案”的主路由责任。

### 3.3 课程

接入系统课程、公开讲座、研究演讲、工程演示和 workshop。获准的 YouTube 官方频道只提供频道 feed 元数据与原始链接；Vault2077 不下载、转录或再发布视频/音频内容。

### 3.4 播客

按权威主理人准入整档节目，不根据单集嘉宾或主题临时取舍。

所有正式来源及完整接入边界以 [SiC 来源目录](Vault2077-SiC-Source-Catalog.md) 为准。目录状态为 `pending_review`、`approved`、`paused`、`retired` 或 `rejected`；只有 approved 来源进入运行时。

## 4. 平台原生榜

### 4.1 固定视图

| 平台 | 视图 | 展示原则 |
| --- | --- | --- |
| OpenGithubs GitHub Rank | Daily / Weekly / Monthly | 通过 GitHub 官方 REST API 读取第三方聚合榜，保留其公开顺序 |
| Hugging Face | Trending | 保留平台公开趋势顺序 |
| OpenRouter | `top-weekly` | 保留提供方周口径 |

### 4.2 禁止事项

- 不设置 MCP 榜。
- 不以本地快照计算 Star、下载量、安装量或排名变化。
- 不把不同平台指标合成“总榜”。
- 不宣称榜单代表质量、安全、能力、商业价值或投资价值。
- 不为缺失数据猜测数值或填充虚假排名。

### 4.3 条目最小字段

每个条目至少包含：平台、平台视图、平台内顺序、名称、原始链接、平台提供的公开描述/指标（若有）、采集时间。中文说明属于 Vault2077 编辑层，不能替换或改变平台排序。

## 5. 上线基线、更新与降级

- 首次正式启用 SiC 前，对每个 approved 内容来源执行一次初始化回填；忽略日常 24 小时增量窗口，向前查找并收录最近一条符合该来源准入边界的真实内容。Hugging Face Weekly Papers 作为集合型来源，回填最新可用 ISO 周的完整清单。
- “最近一条”按原始发布时间判断。没有当天或当周更新不构成空结果；例如播客应回填最近一期，而不是因为本日未更新让播客区块为空。
- 初始化回填不扩大来源边界：播客仍按整档来源、课程仍只取获准入口元数据、档案仍排除新闻稿和例行版本日志。
- 初始化结果保留真实原始发布时间、来源和采集时间，不标为“今日更新”，也不得作为硬编码样例随应用构建发布。
- 除周度论文集合外，每个来源只保证一条上线基线；后续展示更多历史条目必须有独立、受限的回填任务，不得一次把完整历史交给 SiC 编辑配置。论文只保留最新成功周快照，不累积跨周历史。
- 周度论文每天刷新一次当前 ISO 周全集，保存 Hugging Face `paper.upvotes`，在本地按票数降序生成 `weeklyRank`；同票按 Hugging Face 提交时间降序。当前公开存储只保留最新成功周快照，跨周首次成功后旧周退出公开集合。
- 周论文的中文标题、一句话说明与内容摘要必须由境内 `sic_editorial` 完成；只有带 `editorialLocale=zh-CN` 和当前 `editorialVersion` 的完整结果才算处理成功，英文占位复制不得发布。
- 上线基线按内容组和小批次进入 `sic_editorial` 队列，完成处理、去重和发布后再开放频道，避免首次运行造成无界模型并发。
- 小批次可以包含不同来源，但同一来源的一次权威集合不得跨 acquisition 批次拆分；当前合同没有来源分片完成标志，超过单批上限必须失败关闭，不能让首个成功分片提前替换上一成功集合。
- `sic` 采集通道每日北京时间 `08:25` 获取内容源；周论文每次读取本周全集并重排，其余内容源使用 24 小时重叠窗口，随后统一交给独立的 SiC 编辑配置处理。
- SiC 编辑配置强调技术术语忠实、方法、证据、适用条件与局限，不沿用 Vault 的新闻标题和事件判断语气。
- SiC 编辑配置拥有独立于 Vault 的处理队列、并发、超时和熔断；模型请求额度不设上限，但一次 sic 批次的积压或提供方故障不得占满 Vault 事件编排容量。
- SiC 编辑配置只有一个主处理提供方和一个受控备用；同一任务不得随机跨提供方或并行生成后择优，处理结果必须记录提供方、模型、提示和处理版本。
- `rankings` 通道在北京时间 `08:35/12:35/16:35/20:35` 刷新 SiC 榜单；榜单不进入内容摘要处理。
- 页面显示最近成功更新时间。所有内容组和榜单逐来源呈现最近成功发布集合；`success` 才能权威替换该来源集合，`partial` 只合并已完成条目，合法 `empty` 与 `failure` 均保留最后成功结果，不影响其他来源、平台和内容组。单条编辑失败只跳过该条，正常条目继续发布。同一来源同轮分片按最差状态与合计条目数聚合；来源退出 approved 集合后，下一轮处理显式停用该来源的当前公开条目。
- 境内完成编辑的 SiC 条目按稳定身份逐条保存在 PostgreSQL 发布表，状态文档只在上一 release 回滚窗口内作为兼容投影。分页“快照 ID”只冻结一次浏览会话的当前条目清单，不是原始信息库或唯一内容存储；公开页面不得读取 acquisition inbox。
- 公开页面不显示采集、处理、来源或榜单的延迟、堵塞、失败、降级和上一成功快照说明；这些诊断只在受保护的管理域 `/pipeline` 展示。公开页面可以显示最近成功更新时间、榜单采集时间和原始来源，但不得由这些元数据追加运维状态标签。

## 6. 交互与验收

- 默认优先呈现最新内容和各平台当前主视图。
- 栏目定位使用可复制、可返回的 hash；当前榜单使用可复制、可返回的 `board` 查询 URL，并通过 `aria-current`、`aria-hidden` 与受控 `tabIndex` 保留明确的键盘焦点和当前状态。
- 首次 HTML/RSC 只携带各组精编首批的轻量公开投影；论文、档案、课程和播客均在当前页通过只读公开接口每次请求五条，不得把完整当前快照预埋进客户端、一次展开全部记录或跳转到另一界面。
- 同一轮分批读取必须携带首屏为所属内容组生成的快照 ID；各组独立签发，单组读取或补充来源失败不得阻断其他组。服务端该组快照已变化时返回明确的“内容已更新”状态，页面提示用户刷新并停止追加，绝不把两个快照的条目混入同一列表。
- 内容条目与“展开更多”默认保持纸面；鼠标悬停或键盘聚焦时由真实交互盒反色。外侧栏必须顶到视口物理边缘，中间栏必须严格停在真实分割线；窄屏单栏反色同时抵达两侧视口边缘。
- 趋势榜章节带在所有桌面宽度横贯视口，不设置左右边框；左右三角切换必须显示前一、当前、后一平台名称，并同时展示采集时间与原始来源。榜单延迟和失败状态只进入受保护的管线诊断。
- 移动端榜单允许纵向重排，不允许依赖横向拖动才能看见名称与排名。
- 条目外链清楚标识并指向原始平台。
- 标准宽度 `360 / 768 / 1280 / 1440` 无横向溢出。
- 源目录、页面标签与运行时注册表中的平台/内容组名称一致。

## 7. 明确不做

- MCP 排名；
- 自算 GitHub 或 Hugging Face 增长；
- 对榜单项目进行主观推荐；
- 视频、音频下载或转录；
- 用单篇临时挑选替代来源准入。
- 把同一机构发布同时送入 Vault 资讯瀑布和 SiC 档案。

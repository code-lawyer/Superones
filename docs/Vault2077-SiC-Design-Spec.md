# Vault2077 SiC 学院设计规格

## 1. 目标

SiC 学院帮助超级个体持续阅读硅碳共生相关的一手正式内容，并观察主流技术平台公开定义的热度与采用视图。它不是新闻流、课程商城、项目推荐器或质量评分系统。

## 2. 页面结构

`/sic` 由两部分组成：

1. 最新内容：论文、档案、课程、播客。
2. 平台原生榜：GitHub、Hugging Face、OpenRouter。

内容与榜单可以在同页分区或使用页内视图切换，但不得混成一个综合排名。

## 3. 内容组

### 3.1 论文

只接入定义清楚的正式论文发布入口。条目至少展示标题、作者/机构、原始发布时间、来源与原始链接。

### 3.2 档案

只接入机构自营的深度研究、技术报告、系统卡、方法论与长篇工程材料。新闻稿、公司公告、营销活动、例行 Release Notes 与 Changelog 不属于档案；其中新闻型内容进入 Vault 资讯瀑布，深度材料不得在那里重复发布。不得把个人解读或二次复现冒充官方档案。

宽泛混合 Feed 只有在能通过固定栏目、路径或专用入口稳定排除新闻与营销内容时才可批准；不得让境内 LLM 承担逐篇决定“进资讯还是进档案”的主路由责任。

### 3.3 课程

接入系统课程、公开讲座、研究演讲、工程演示和 workshop。获准的 YouTube 官方频道只提供频道 feed 元数据与原始链接；Vault2077 不下载、转录或再发布视频/音频内容。

### 3.4 播客

按权威主理人准入整档节目，不根据单集嘉宾或主题临时取舍。

所有正式来源及完整接入边界以 [SiC 来源目录](Vault2077-SiC-Source-Catalog.md) 为准。目录状态为 `pending_review`、`approved`、`paused`、`retired` 或 `rejected`；只有 approved 来源进入运行时。

## 4. 平台原生榜

### 4.1 固定视图

| 平台 | 视图 | 展示原则 |
| --- | --- | --- |
| OpenGithubs GitHub Rank | Daily / Weekly / Monthly | 通过 GitHub 官方 REST API 读取第三方聚合榜，保留其公开顺序 |
| Hugging Face | Trending | 保留平台公开趋势顺序 |
| OpenRouter | `top-weekly` | 保留提供方周口径 |

### 4.2 禁止事项

- 不设置 MCP 榜。
- 不以本地快照计算 Star、下载量、安装量或排名变化。
- 不把不同平台指标合成“总榜”。
- 不宣称榜单代表质量、安全、能力、商业价值或投资价值。
- 不为缺失数据猜测数值或填充虚假排名。

### 4.3 条目最小字段

每个条目至少包含：平台、平台视图、平台内顺序、名称、原始链接、平台提供的公开描述/指标（若有）、采集时间。中文说明属于 Vault2077 编辑层，不能替换或改变平台排序。

## 5. 上线基线、更新与降级

- 首次正式启用 SiC 前，对每个 approved 内容来源执行一次初始化回填；忽略日常 24 小时增量窗口，向前查找并收录最近一条符合该来源准入边界的真实内容。
- “最近一条”按原始发布时间判断。没有当天或当周更新不构成空结果；例如播客应回填最近一期，而不是因为本日未更新让播客区块为空。
- 初始化回填不扩大来源边界：播客仍按整档来源、课程仍只取获准入口元数据、档案仍排除新闻稿和例行版本日志。
- 初始化结果保留真实原始发布时间、来源和采集时间，不标为“今日更新”，也不得作为硬编码样例随应用构建发布。
- 每个来源只保证一条上线基线；后续展示更多历史条目必须有独立、受限的回填任务，不得一次把完整历史交给 SiC 编辑配置。
- 上线基线按内容组和小批次进入 `sic_editorial` 队列，完成处理、去重和发布后再开放频道，避免首次运行造成无界模型并发。
- `sic` 采集通道每日北京时间 `07:25`、`19:25` 获取内容源，使用 24 小时重叠窗口并交给独立的 SiC 编辑配置处理。
- SiC 编辑配置强调技术术语忠实、方法、证据、适用条件与局限，不沿用 Vault 的新闻标题和事件判断语气。
- SiC 编辑配置拥有独立于 Vault 的处理队列、并发和预算；一次 sic 批次的积压或提供方故障不得占满 Vault 事件编排容量。
- SiC 编辑配置只有一个主处理提供方和一个受控备用；同一任务不得随机跨提供方或并行生成后择优，处理结果必须记录提供方、模型、提示和处理版本。
- `rankings` 通道每小时唤醒，但只在对应平台榜到期时刷新 SiC 榜单；榜单不进入内容摘要处理。
- 页面显示最近成功更新时间。单个平台失败时保留其最后成功结果并标注过期，不影响其他平台和内容组。
- 公开页面只说明“暂时无法更新/最后更新时间”，不展示源站错误、网络拓扑、密钥、模型或内部阈值。

## 6. 交互与验收

- 默认优先呈现最新内容和各平台当前主视图。
- 视图切换必须保留键盘焦点和选中状态。
- 移动端榜单允许纵向重排，不允许依赖横向拖动才能看见名称与排名。
- 条目外链清楚标识并指向原始平台。
- 标准宽度 `360 / 768 / 1280 / 1440` 无横向溢出。
- 源目录、页面标签与运行时注册表中的平台/内容组名称一致。

## 7. 明确不做

- MCP 排名；
- 自算 GitHub 或 Hugging Face 增长；
- 对榜单项目进行主观推荐；
- 视频、音频下载或转录；
- 用单篇临时挑选替代来源准入。
- 把同一机构发布同时送入 Vault 资讯瀑布和 SiC 档案。

# Vault2077 负责人纸质结账启用手册

> 本手册已被 ADR-0020、ADR-0022 与《OPC 线下付款资料替换与启用手册》取代，只作为历史决策证据保留，不得用于排障、恢复旧渠道或开放新订单。

本文只指导负责人完成 Vault2077 纸质签约、支付宝全额预付和付款通知上线中必须由真人、商家主体或资金责任人完成的事项。工程命令、服务器配置、备份、部署、探针、迁移、监控和回滚由工程代理执行；负责人不需要手工编辑数据库，也不需要把任何秘密贴到聊天、GitHub、截图或工单。

当前线上代码已经具备纸质订单、支付宝支付/查询、全额退款/退款查询、付款凭证、付款邮件 outbox、后台合同门禁和联系方式清理能力。真实入口保持关闭，直到本文全部通过。电子签约继续关闭；纸质签约不要求开通 e 签宝。

## 1. 先看结论：哪些必须由你本人完成

| 事项 | 必须由你本人完成的原因 | 可以交给工程代理的部分 |
| --- | --- | --- |
| 支付宝商家主体认证、产品签约、应用审核 | 涉及法定主体、账户实名、协议接受和二次验证 | 检查应用配置字段、接入代码、回调与签名逻辑 |
| 支付宝应用密钥最终托管 | 应用私钥代表商户发起支付和退款，负责人必须控制其保管边界 | 协助生成、检查格式并写入受控服务器；不在聊天展示值 |
| SMTP 邮箱登录、开启服务、生成授权码 | 需要邮箱账户登录和二次验证 | 配置服务器、测试 TLS、验证 outbox 重试 |
| 两枚生产 Passkey 注册和恢复码保存 | 必须使用负责人的真实设备、生物/PIN 和离线介质 | 生成短时注册令牌、检查会话和审计状态 |
| 真实服务、价格、履约人和纸质合同流程确认 | 这是对客户的经营承诺，代码不能代替负责人决定 | 把确认结果录入后台草稿并执行发布检查 |
| 真实小额付款与全额退款授权 | 涉及真实资金、付款账户、会计处理和退款结果 | 监控订单、核验通知、执行后台退款并保存脱敏证据 |
| 最终 Go/No-Go | 负责人承担经营、资金、隐私和履约责任 | 汇总门禁证据并给出工程建议 |

除上述事项外，服务器命令、环境变量校验、支付宝 API 探针、systemd、数据库备份和迁移、日志检查以及功能开关均由工程代理完成。

## 2. 安全规则

以下内容永远不要发到聊天、邮件正文、截图、GitHub 或普通文档：

- 支付宝应用私钥全文；
- SMTP 授权码或邮箱登录密码；
- Passkey 恢复码；
- 数据库连接串；
- 服务器生产环境文件全文；
- 支付宝、阿里云或 GitHub 的 AccessKey Secret、Token。

可以交付给工程侧的证据只有：字段是否已配置、应用/商户编号后四位、开通的产品名称、审核状态、测试订单号、退款请求号、时间和通过/失败结论。测试订单号和退款号只能进入本机私有运维记忆，不提交公开仓库。

如果由你亲自向服务器录入秘密，请使用受控 SSH 会话和 `sudoedit /etc/vault2077/production.env`。不要执行 `cat`、`env`、`printenv`，不要把文件复制到项目目录。更推荐由密码管理器或受控秘密存储注入；完成后只告诉工程代理“字段已配置”。

## 3. 第一阶段：先做六项负责人决定

在登录任何控制台前，先写下以下决定。不要先开通再临时决定业务规则。

1. 支付方式：`page`、`wap` 或 `both`。
   - 电脑和普通桌面浏览器使用电脑网站支付 `page`。
   - 手机浏览器使用手机网站支付 `wap`。
   - 如果支付宝应用只签约了其中一种，生产配置不得填 `both`。
2. 付款通知发件邮箱。建议使用独立运营邮箱，不使用个人日常邮箱；固定收件人仍是生产 owner 邮箱。
3. 真实测试买家、测试日期、允许支付的金额和退款验收人。
4. 用于测试的真实可履约服务、公开价格和负责人。价格必须是服务器已发布目录中的真实固定价格，不能由浏览器临时改成一分钱。
5. 纸质合同由谁打印、联系、寄送、接收返件和判断“合同门禁通过”。这些线下动作不进入系统，但必须有人负责。
6. 测试失败时谁可以立即关闭入口、谁负责查看支付宝账单和谁决定退款。

完成后向工程侧交付以下非秘密文本：

```text
支付模式：page / wap / both
付款通知发件邮箱：已确定
真实测试服务编号：
公开价格：
测试买家：已确定
测试金额及退款：已授权
纸质合同运营负责人：
Go/No-Go 负责人：
```

## 4. 第二阶段：完成支付宝商家应用

### 4.1 登录与主体核对

1. 打开[支付宝开放平台](https://open.alipay.com/)，使用合同责任主体控制的商家账号登录。
2. 核对账户已完成企业/商家实名认证，结算账户和联系人仍有效。
3. 核对应用所属主体与网站公开经营者、合同收款主体一致。主体不一致时停止，不要用个人账户、个人收款码或其他公司的应用代替。
4. 在[网页/移动应用](https://open.alipay.com/module/webApp)中检查是否已有专用于 Vault2077 的应用；没有时创建网页/移动应用，填写真实应用名称、网站、用途和所需资料。

支付宝当前公开接入流程仍是“创建应用 → 开发配置 → 提交审核和上线”；只有审核上线后才能使用对应线上能力。

### 4.2 开通支付产品

在应用或商家产品页面确认：

- 使用 `page` 时已开通电脑网站支付；
- 使用 `wap` 时已开通手机网站支付；
- 使用 `both` 时两项都已开通；
- 应用状态为已上线，不是开发中、审核中或已下架；
- 支付、交易查询、交易关闭、交易退款和退款查询能力可用；
- 退款期限、费率、结算周期和退款时手续费规则已经由负责人阅读并接受。

不要为了“先跑起来”使用静态个人收款码。Vault2077 使用每订单动态收银台和服务器端订单金额。

### 4.3 配置 RSA2 密钥

1. 在支付宝应用“开发设置/接口加签方式”中选择 RSA2。
2. 使用支付宝官方密钥工具或受控离线环境生成一对应用密钥。
3. 将“应用公钥”上传到支付宝开放平台。
4. 从支付宝平台取得与该应用对应的“支付宝公钥”。
5. 将“应用私钥”保存到密码管理器或直接写入服务器秘密环境。

必须区分：

- 应用公钥：上传给支付宝，不填入 Vault2077 的 `VAULT2077_ALIPAY_PUBLIC_KEY`；
- 应用私钥：填入 `VAULT2077_ALIPAY_PRIVATE_KEY`，不得上传 GitHub；
- 支付宝公钥：填入 `VAULT2077_ALIPAY_PUBLIC_KEY`，用于验证支付宝响应和通知；
- 密钥格式：项目支持 `PKCS8` 或 `PKCS1`，`VAULT2077_ALIPAY_KEY_TYPE` 必须与真实私钥一致。

不要截取、重排或人工删除 PEM 内容。若环境文件用单行保存，换行由工程侧按程序支持的 `\n` 形式处理。

### 4.4 核对生产参数

生产需要以下字段，但不要把值发给工程代理：

| 字段 | 负责人在控制台确认的来源 |
| --- | --- |
| `VAULT2077_ALIPAY_APP_ID` | 已上线应用的 APPID |
| `VAULT2077_ALIPAY_SELLER_ID` | 实际收款商户 PID |
| `VAULT2077_ALIPAY_PRIVATE_KEY` | 与上传应用公钥配对的应用私钥 |
| `VAULT2077_ALIPAY_PUBLIC_KEY` | 支付宝为该应用提供的支付宝公钥 |
| `VAULT2077_ALIPAY_KEY_TYPE` | `PKCS8` 或 `PKCS1` |
| `VAULT2077_ALIPAY_GATEWAY` | 生产固定 `https://openapi.alipay.com/gateway.do` |
| `VAULT2077_ALIPAY_WEB_PAYMENT_MODE` | 与已签约产品一致的 `page`、`wap` 或 `both` |

Vault2077 自动使用以下公网地址：

- 异步通知：`https://superones.top/api/opc/alipay/notify`
- 浏览器返回：`https://superones.top/opc/payment/return`

通知地址必须能直接接收支付宝 POST，不得跳转。支付宝的[异步通知说明](https://aipay.alipay.com/docs/ai-web-app-payment-qianyi/api-list/async-notify-verify.html)要求商户同时接入异步通知和主动查询；验签后还必须核对订单号、金额、seller 和 APPID。项目代码已经执行这些核验，浏览器返回页不会直接确认到账。

### 4.5 你要保存的非秘密证据

- 应用名称与状态；
- APPID 后四位；
- 商户 PID 后四位；
- 已开通产品：电脑网站支付、手机网站支付或两者；
- RSA2 已配置；
- 支付宝公钥取得日期；
- 费率、结算周期、退款期限的确认日期；
- 控制台负责人姓名。

不要在截图中露出完整密钥、完整 PID、身份证件、手机号或账户余额。

## 5. 第三阶段：配置付款通知邮箱

代码支持任何提供 TLS 的 SMTP 服务。当前建议配置为 163 邮箱的隐式 TLS：

```dotenv
VAULT2077_SMTP_HOST=smtp.163.com
VAULT2077_SMTP_PORT=465
VAULT2077_SMTP_USER=<已开启 SMTP 的完整邮箱地址>
VAULT2077_SMTP_PASSWORD=<客户端授权码，不是网页登录密码>
VAULT2077_SMTP_FROM=<与服务端授权一致的发件地址>
```

由你本人完成：

1. 登录选定的发件邮箱。
2. 在邮箱设置中开启 SMTP/客户端服务。
3. 按邮箱服务商要求完成手机或二次验证。
4. 生成独立客户端授权码；不要复用网页登录密码。
5. 把授权码保存到密码管理器或服务器秘密环境。
6. 向工程侧只报告 host、port、发件地址和“授权码已配置”，不要报告授权码。

工程侧随后会验证：

- TLS 证书校验开启；
- 465 使用隐式 TLS，其他端口强制 STARTTLS；
- 能向固定 owner 邮箱发送一封脱敏测试邮件；
- 暂时失败时 outbox 重试使用同一个 Message-ID；
- 支付宝回调不等待 SMTP，因此邮件故障不会改变到账状态。

付款邮件只包含订单号、服务、金额、付款时间、支付宝交易号和后台链接，不包含客户完整姓名、手机号、邮箱或寄送地址。

## 6. 第四阶段：注册生产 Passkey

此项必须使用真实 HTTPS 管理域名和你的实体设备。

1. 让工程代理生成十分钟有效的一次性注册令牌。
2. 在你的设备上打开 `https://admin.superones.top/admin`。
3. 注册第一枚 Passkey；完成设备 PIN、生物识别或硬件密钥验证。
4. 立即把首次显示的恢复码保存到离线密码库或密封纸质介质，不截图、不发聊天。
5. 登录后台后注册第二个独立认证器。优先使用不同设备或独立硬件密钥，不能只依赖同一设备的一个副本。
6. 实际测试登录、注销、重新登录和需要最近五分钟再认证的高风险操作。
7. 在工程代理陪同下消费一条恢复码，确认只能使用一次；剩余恢复码继续离线保存。

交付证据：凭证数量、设备类型、注册日期、恢复演练日期和结果。不要交付凭证标识全文或恢复码。

## 7. 第五阶段：确认真实服务和纸质合同运营

付款入口不能对一个虚构、不可履约或临时测试服务开放。你需要在后台确认至少一个真实服务：

- 名称和服务编号；
- 固定人民币价格；
- 服务范围与明确排除项；
- 客户需要提供的材料；
- 交付成果、周期和验收标准；
- 取消与全额退款规则；
- 实际履约负责人；
- 自然人或法人/组织签约适用范围。

纸质合同线下流程至少明确：谁打印、谁寄送、寄送地址如何取得、谁接收返件、谁判断签署有效、纸质原件保管位置、发生异常时谁决定全额退款。系统不会自动创建寄件、返件、催办或纸质文件核验任务。

如果法律文本、公开经营者、统一社会信用代码、ICP、退款规则或实际流程有变化，必须先更新并重新签字，不能只改环境开关。

支付产品：page / wap / both
APPID：仅后四位
商户 PID：仅后四位
应用私钥：已安全写入生产秘密环境

SMTP：已开启并写入授权码
发件邮箱：可公开的邮箱地址
两枚 Passkey：已注册 / 尚未注册

不要附环境文件、密钥文件、授权码或控制台秘密截图。

## 9. 工程代理随后会做什么

以下步骤不需要你执行命令：

1. 备份生产环境文件和 RDS。
2. 保持三个开关关闭，检查新增字段完整性和文件权限。
3. 运行 `opc:verify-providers`；电子签约关闭时探针明确报告 `esign.status=disabled`，只执行支付宝无资金查询，不要求 e 签宝凭据。
4. 对支付宝正式网关执行无资金的保留订单查询探针，确认 APPID、商户 PID、私钥、支付宝公钥、RSA2 和网络可用。探针不会创建或支付订单。
5. 对 SMTP 执行真实 TLS 测试，只发送脱敏测试邮件。
6. 运行 `deploy:check`、数据库迁移/集成测试、后台鉴权和 Nginx 边界检查。
7. 在纸质入口仍关闭时启用付款配置和邮件配置，确认没有公开表单。
8. 选择受控测试窗口，临时开放纸质入口完成真实交易；失败时立即关闭入口，不手工改数据库。
9. 核验 health、订单状态、付款凭证、邮件、审计和退款证据。
10. 只有全部通过后才启用 maintenance timer 并长期保持纸质入口开放。

工程侧最终生产目标值为：

```dotenv
VAULT2077_OPC_PAYMENTS_ENABLED=true
VAULT2077_OPC_PAYMENT_EMAIL_ENABLED=true
VAULT2077_OPC_PAPER_CHECKOUT_ENABLED=true
VAULT2077_OPC_ESIGN_ENABLED=false
```

前三个值不能跳步一次性盲开。电子签约保持 `false`，不影响纸质订单。

## 10. 第七阶段：真实付款和退款验收

### 10.1 付款前

你需要在测试窗口现场确认：

- 测试服务和价格是真实经营内容；
- 测试买家知情并同意真实扣款；
- 支付账户可用；
- 测试金额和可能产生的手续费已获批准；
- 退款验收人可以查看买家实际到账；
- 工程代理已准备立即关闭入口的回滚命令。

### 10.2 付款过程

1. 从公开服务详情进入纸质签约。
2. 选择自然人或法人/组织；法人首期只允许法定代表人本人。
3. 填写测试买家的真实必要信息和寄送地址，不使用虚构身份证明。
4. 阅读并下载在线订单及预付款协议。
5. 主动勾选同意，确认服务、金额、纸质合同前不启动服务和全额退款规则。
6. 创建订单，核对跳转域名是支付宝官方域名、金额与公开价格一致。
7. 完成真实支付；不要把付款截图当作到账证据。

工程代理核对：异步通知验签、APPID/PID、订单号、金额和状态，或通过 `alipay.trade.query` 主动查询。支付宝官方说明要求只有 `TRADE_SUCCESS` 或 `TRADE_FINISHED` 才能判为成功；缺失异步通知时必须主动查询。

### 10.3 到账后

确认以下证据：

- 订单从“待付款”进入“已付款待合同确认”；
- 没有直接进入“已到账可履约”；
- 只生成一张付款凭证；
- 只生成一个付款邮件 outbox 事件；
- 固定 owner 邮箱收到一封脱敏付款通知；
- 浏览器返回页本身没有改变订单状态；
- 后台默认遮罩联系人和寄送地址，查看完整值需要最近五分钟再认证并记录审计。

### 10.4 全额退款验收

在纸质合同未完成或负责人决定退款的真实订单上：

1. 由负责人在后台确认“发起全额退款”。
2. 核对金额必须等于服务器保存的原订单全额，不扣打印、寄送或其他费用。
3. 订单先进入“退款处理中”，不得人工改成“已退款”。
4. 网络超时或结果不明确时，工程侧用同一个稳定退款请求号查询，不能换号重复退款。
5. 支付宝确认后，订单才能进入“已全额退款”。
6. 测试买家确认资金实际原路退回；银行卡到账时间以银行处理为准。

支付宝当前[退款接口说明](https://aipay.alipay.com/docs/mobile-app-pay/ai-app-pay/alipay-trade-refund.html)要求同一退款请求重试保持相同 `out_request_no`；`code=10000` 本身不等于退款最终成功，结果不明确时必须继续查询。项目已经采用稳定退款请求号和退款查询路径。

如果还要验证“合同门禁通过”分支，只能使用已真实完成纸质合同核验的订单。不得为了测试在生产后台虚假记录合同已签署。

## 11. 最终启用条件

以下任何一项为否，就保持纸质入口关闭：

- [ ] 支付宝应用已上线，签约产品与 `page/wap/both` 一致；
- [ ] 支付宝应用私钥、支付宝公钥和商户 PID 已安全配置；
- [ ] 无资金支付宝查询探针成功；
- [ ] SMTP TLS 测试成功；
- [ ] 两枚 Passkey 和恢复演练完成；
- [ ] 至少一个真实服务可履约，价格与协议一致；
- [ ] 纸质合同线下负责人和退款负责人已确认；
- [ ] `deploy:check`、数据库、Web、Nginx 和权限边界全绿；
- [ ] 四通道业务 health 全绿或负责人对明确降级作出书面 Go/No-Go；
- [ ] 真实付款、到账、凭证、邮件和全额退款闭环通过；
- [ ] OPC maintenance oneshot 成功且告警有效；
- [ ] 负责人签署最终 Go。

全部通过后，工程代理负责启用 `vault2077-opc-order-maintenance.timer`，再打开纸质结账总开关并持续观察日志、支付宝通知、订单 outbox 和退款状态。

## 12. 紧急关闭与事故处理

发现价格错误、商户不匹配、异常通知、邮件泄露、重复订单、退款不确定或后台不可用时：

1. 工程代理先把 `VAULT2077_OPC_PAPER_CHECKOUT_ENABLED=false` 并重启 Web，阻止新订单。
2. 不删除 RDS、不删除订单、不手工改订单状态。
3. 已付款订单继续通过支付宝主动查询核对，不能因为关闭入口而忽略。
4. 退款结果不确定时使用原退款请求号查询；不得创建新请求号碰碰运气。
5. 保留订单号、时间、接口结果类别和审计证据，但不保存密钥、完整客户资料或生产环境文件。
6. 由负责人决定已付款订单继续履约还是全额退款。

付款功能关闭不影响主站、内容频道和后台只读运营。若 SMTP 单独故障，支付宝到账状态仍可确认，但必须暂停新订单或尽快恢复 outbox，不能靠手工邮件冒充系统已发送。

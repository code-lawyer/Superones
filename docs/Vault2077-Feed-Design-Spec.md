# Vault2077 信息流首版设计基线

> 冻结日期：2026-07-22。本文件记录 Vault 信息流公开产品与页面的首版边界。来源分工遵循本文件、SiC 规格与 ADR-0008；采集连接器和人工纠错后台另行设计。

## 1. 产品任务

Vault 信息流不是新闻数据库，也不声称检索字面意义上的整个互联网。它持续整理主要来自国际互联网的高价值 AI 新闻型公开信息：第三方报道、机构正式新闻和开源项目重大版本先流经资讯瀑布，形成明确意义后再沉淀进事件簿，让用户在约五分钟内理解近期主要变化，并能够返回每一条原始来源核验。机构深度研究与技术材料进入 SiC 档案，不在资讯瀑布重复发布。内容语言不限，但中国大陆来源平台不进入来源组合。

主标语为“维度收束，视界引擎”。产品不提供搜索、个性化、订阅、评论、聊天问答或热度评分。

## 2. 领域模型

- **资讯**是保留原始语言内容、中文处理结果、来源、作者和原始时间的原子信息。
- **事件**是由多条资讯共同支撑的意义单元，一个事件包含完整资讯集合。
- 同一资讯可以关联多个事件；在资讯瀑布中只出现一次，并拥有一个主事件。
- 资讯瀑布是当前快照层，只执行翻译和单条摘要；事件簿是唯一长期沉淀层，形成事件时把所用资讯的必要证据副本写入事件。
- 事件只有一个主分类：模型与产品、研究与能力、公司与市场、政策与安全、开源与生态。
- 资讯只有一个来源角色：官方、媒体、测试、评论、研究。
- 每条资讯继承发布通道的发布实体、发布者性质和证据性质基线；来源角色是条目级判断，可以覆盖通道基线。
- 经来源注册表逐项批准的第三方聚合 API 或 RSS 可以作为生产传输路径；聚合器本身不构成事实来源，条目必须保留原始发布者、canonical URL、作者与原始时间。参考项目仍只用于准入前发现候选。
- Hacker News 与 Lobsters 已退出生产来源。Follow Builders X 中央 feed 的上游选择默认可信并完整接入；经产品批准，该补充入口统一使用 `ownerEntity=aggregator:follow-builders` 与 `publisherKind=aggregator`，不逐账号维护实体类型。每条内容仍保留原账号名称、账号标识、status ID 与原始 X URL；该简化不得改变公开署名，也不得进入资讯事件的发布实体多样性计算。
- 每条原始内容只有一个公开主去向；其他栏目可以引用其稳定 ID，不得再次采集或重复发布正文。

### 2.1 信源准入硬边界

- 准入判断针对原始发布通道，不针对内容语言、作者国籍、机构国籍或讨论主题。
- 微信公众号、小红书、知乎、微博、小宇宙、头条、抖音、B 站和大陆媒体热榜等大陆来源平台不得进入生产来源组合，包括经 RSSHub、Wechat2RSS、NewsNow 等代理转出的内容。
- X、GitHub、Reddit、Telegram、海外播客平台和经批准的境外独立网站可以承载任何语言；其中有价值的中文资讯正常采集，并保留原文。
- YouTube 及其他视频专属通道不进入来源注册表或候选池。系统不下载视频、不提取音频、不抓取第三方字幕，也不承担视频转写与摘要；同一内容如有官方文章、论文、仓库或正式文字稿，只采集相应文本来源。
- 代理和第三方聚合服务只记录为传输路径。只有提供稳定 API 或 RSS、能够还原原始发布者与 canonical URL、并经来源注册表批准的聚合入口才能用于生产；不得递归抓取目标网页，不得用代理服务器所在地替代原始平台，也不得用原文语言推断平台归属。
- Follow Builders X 不执行本地账号准入或构建时去重；运行时仍须验证合法帖子 ID、匹配账号的 canonical X URL、发布时间和 feed 新鲜度。机构账号与新增账号随上游 feed 自动进入 roadside。
- Follow Builders Blogs 与 Podcasts 中央 feed 直接作为 SiC documents/podcasts 的正文与转录入口，不再逐源访问官网 sitemap/RSS，也不按招聘或营销关键词过滤。

事件晋升的自动判断门槛为：至少三条资讯、至少两个不同发布实体、至少两种来源角色；同一实体的博客、X、播客或多个代理入口只算一个独立发布者。存在官方一手来源时必须纳入；多条资讯必须指向同一方向。产品发布和版本变化通常使用 72 小时时间窗，趋势与采用变化最多使用 14 天时间窗。

## 3. 页面结构

### 3.1 信息流首页

页面顶部沿用其他三个板块的统一大标语结构：小号频道编号、大标题“维度收束，视界引擎”、一句关系说明和最近一次成功发布批次的北京时间。不得解释服务器位置、模型名称或内部阈值。

大标语下方同时呈现左右两栏，不提供标签页或视图切换：左侧是事件簿，右侧是资讯瀑布。删除搜索框、搜索索引和搜索结果页。

### 3.2 事件簿

- 按最后一次实质更新的自然日分组，日期只出现一次。
- 首批显示最近 10 个事件，继续加载时每批 10 个。
- 单条只显示事件标题和灰色一句话判断，不展示摘要、实体、资讯数量、来源比例或更新时间。
- 事件标题最多 28 个中文全角字符，标点计入，ASCII 字符约按半个计算；最多两行，超长由 LLM 重写，不依赖截断。
- 一句话判断最多 20 个全角字符，必须保持单行；标题说明发生了什么，判断说明这意味着什么。
- 旧事件不显示结束、归档或前序关系，随新事件自然下沉。

### 3.3 资讯瀑布

- 内容边界只包括新闻型材料：第三方完整报道，机构公告、产品发布、公司变化、政策回应，以及获准开源项目的重大版本。
- 研究论文、技术报告、系统卡、方法论、长篇工程文章、例行 Release Notes 与 Changelog 不进入资讯瀑布；其中具有长期阅读价值的材料按 SiC 目录进入档案。
- 按原始发布时间倒序；无可靠发布时间时使用首次发现时间并标注“时间未注明”。
- 首批显示 5 条，后续内容默认折叠；展开后按 5 条递增加载。
- 每条资讯只显示中文标题和灰色原文标题，不在瀑布中显示摘要、来源、时间、角色或沉淀状态。
- 中文标题最多 36 个全角字符、最多两行；原文标题保持单行，超长时截断。原文即为中文时仍保留原始措辞。
- 点击先进入 Vault 资讯详情，不直接离站；详情提供明确的“查看原始来源”。
- 尚未归入事件的资讯只存在于最近 30 天滚动窗口，不构成历史档案。归入事件后，事件保存当时使用的标题、摘要、必要正文、来源和原始时间；资讯离开滚动窗口后事件详情仍可完整展示证据。

### 3.4 导航

- 事件簿与资讯瀑布均不提供标签或筛选区，进入页面即阅读完整的连续信息流。
- 两栏各自保留“继续加载”，加载批次共同写入 URL。浏览器返回时应恢复加载批次和滚动位置；主动点击导航中的“信息流”则回到最新完整页面。

## 4. 事件详情

详情首屏按“结论先行”组织：分类与最后更新时间、事件标题、一句话判断、灰色说明“由 AI 基于公开来源自动编排”。说明链接到公开方法页。

正文顺序：

1. 300–500 个中文字符的综合摘要，分为 3–5 个短段落。
2. 核心实体。
3. 完整相关资讯集合和最后更新时间。

综合摘要先说明确认事实，再归纳测试、评论或市场反应，最后说明意义和不确定部分。关键事实和一句话判断必须以 `[1]` 形式关联证据；点击编号定位到对应资讯。找不到来源的事实不得发布。

相关资讯不得由 AI 选择性删减。默认展开 20 条，继续加载直到全部可访问；按原始发布时间正序排列，形成事件发展记录。来源失效时保留资讯元数据、中文处理结果和失效状态。

## 5. 资讯详情与双语内容

资讯详情展示中文标题、中文摘要、中文处理结果、原文标题、允许公开的原文或必要摘录、原文语言、来源、作者、来源角色、原始北京时间、所属事件和原始来源外链。社区条目详情以社区讨论页为原始来源，并可另列“条目指向的外链（未递归抓取）”。

境外传入的原始字段不可被翻译覆盖：

```text
original_title
original_content
original_language
translated_title_zh
translated_content_zh
```

正文格式是原子资讯的事实元数据。跨境内容合同允许 `plain_text` 与 `markdown` 两种 `contentFormat`；旧批次缺少该字段时按正文结构确定默认值，不能因此覆盖或改写 `original_content`。采集、境内处理和存储必须保留段落、列表、链接与代码块边界，不得把块级正文压成单行。

资讯详情对 Markdown 只渲染受控子集：标题、段落、列表、引用、表格、HTTP/HTTPS 链接、行内代码与代码块。原始 HTML、脚本、图片嵌入、相对链接和非 HTTP(S) 协议不得进入可执行页面结构；不合格链接退化为普通文本。资讯瀑布列表仍只显示经过处理的标题，不显示 Markdown 语法或正文片段。`contentFormat` 只描述正文承载格式，不改变频道准入规则；例行 Release Notes、Changelog 仍不得因为可以安全渲染而进入资讯瀑布。

普通第三方来源公开原始标题、作者、时间、链接、Vault 中文摘要及必要原文短摘录。除事件证据副本外，不保存超过 30 天滚动窗口的资讯历史；只有开放许可、公共领域或明确授权内容才公开全文和全文翻译。GitHub README 依仓库许可证处理。

## 6. 自动编排规则

- information、roadside 的翻译、单条摘要及其形成的事件编排统一使用 Vault 编辑配置；不得让不同提供方随机处理同一语义链路，避免标题、证据措辞和事件归属标准漂移。
- Vault 编辑配置对每条新资讯比较近一个月活跃事件的标题和摘要，决定加入现有事件、保持独立或与其他独立资讯组成新事件。
- 事件新增资讯时可更新标题、判断和摘要，但稳定 ID 与 URL 不变；事件保留当前综合结果和累计证据，不另建可编辑的资讯历史。
- 一个事件连续 30 天没有新资讯后退出匹配名单，前端不做特殊表示。
- 已发布事件归属不由后台人工修改。问题报告进入审计并可触发带稳定任务 ID 的自动重放；自动处理不能证明新结果更可靠时保留现状。
- 每次处理记录提供方、模型、提示版本和处理版本；这些字段只供内部追溯，不进入公开页面。
- Vault 编辑配置只有一个主处理提供方和一个受控备用。主提供方达到明确失败条件后才切换备用；同一任务不得跨多个提供方并行生成后择优。
- 低置信度归属保持为独立资讯。翻译或摘要失败可在同一配置内回退重试一次，再失败则隔离、重新抓取，最终失败时丢弃公开内容但保留内部指标与指纹。

## 7. 更新与状态

- 首次正式启用 Vault 前，应使用最近 30 天的真实新闻型内容建立上线基线，并按正常来源准入、事件晋升、证据和编辑规则处理；不得简单为每个来源抓取一条历史新闻来填满页面。
- 如果 30 天窗口内不足以形成可发布事件，页面应如实保留资讯或明确空状态，不得扩大窗口直到找到陈旧新闻，也不得使用代码内样例冒充当前事件。
- 上线基线完成后，information 与 roadside 回到各自增量窗口；稳定来源 ID、内容指纹和幂等规则必须防止首个增量批次重复发布基线内容。
- `information` 通道在北京时间 08:05–22:05 每两小时运行，使用 24 小时重叠窗口；`roadside` 在 08:55–22:55 每两小时运行。00:00–08:00 不采集，两者共享协议但独立调度和重试。
- 每个来源完成境内处理后独立原子发布；页面“最后更新”取各来源最近成功快照的最晚时间。单条或单来源失败不阻塞同批其他合格内容。普通来源失败仍触发 workflow 失败关闭；注册表显式标记为 `isolated` 的补充来源只报告失败、保留上一成功快照，不得阻断 workflow。
- 境内 inbox 对瞬时失败项执行最多六次指数退避，默认以五分钟为基数、单次等待最多六小时；发布与重试均保持幂等。
- 页面不轮询、不自动刷新、不通知新批次；用户自行刷新获取最新结果。
- 始终保留上一轮成功内容。处理中的文字为“本轮信息正在编排”，筛选无结果为“此维度暂无事件”，批次延迟为“本轮信息尚未抵达，上一轮内容仍可阅读”。不得把模型错误和采集日志暴露给用户。
- 所有公开时间统一换算为北京时间。列表使用 `07.22 · 16:40`，详情使用 `2026.07.22 16:40 UTC+8`。

## 8. 视觉与首页关系

信息流沿用 Vault2077 已确认的纸张灰阶、编辑式字体层级、直角边界和整行反色，不建立独立卡片语言。桌面约以 `60 : 40` 分为左侧事件簿和右侧资讯瀑布：左侧条目更大、更疏、更重，并以带日期的粗线划分每日事件；右侧条目更小、更密、持续向下。移动端按事件簿、资讯瀑布顺序纵向排列。悬浮和键盘聚焦时，左栏所有反色横条从浏览器左边缘贯通至中间分割线，右栏所有反色横条从中间分割线贯通至浏览器右边缘；“继续翻阅事件”和“继续接收资讯”等行尾操作遵守同一规则，不得缩在内容宽度内。移动端反色横条左右双向贯通。标题或操作文字轻微右移并放大；减少动态效果设置下取消位移。

Vault2077 首页只展示最近 3–4 个事件，数量由布局空间决定；首版桌面和移动端均以 3 个为基准。首页不混入原子资讯，不单独编辑数据，也不展示频道标语。

## 9. 公开方法与纠错

“关于信息流”公开解释资讯与事件的定义、事件晋升、来源追溯、双语保留、定时更新、自动编排、匿名纠错以及版权原则。不得公开服务器位置、跨区域结构、模型名称、提示词、阈值参数和采集配置。

事件和资讯详情可提供匿名“报告问题”入口，类型为误合并、信息错误、来源失效。报告只形成审计记录或自动重放信号，不授予后台人工改写资讯、事件或证据的能力。

## 10. 首版验收

- 用户只读最近 10 个事件，可在约 5 分钟内理解近期主要 AI 变化。
- 每个事件由多条资讯支撑，关键结论可定位到具体原始来源。
- 用户能从事件进入完整资讯集合，并核对中文处理结果与原始语言内容。
- information 与 roadside 通道可以按各自节奏自动完成；单来源或单批失败不会清空既有信息流。
- 360px、768px、1280px 和 1440px 宽度下，标题、判断、双语资讯和元数据均不破版；320px 只作为额外压力测试。

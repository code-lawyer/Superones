# Vault2077 后台与运营首版设计基线

> 状态：规范性文件。后台服务于极简运营，不改变公开产品的自动化原则。

## 1. 后台任务

后台只处理 OPC 与边境计划的真实业务输入、外部依赖故障的只读诊断，以及必须人工完成的资格或专业确认。用户问题报告直接写入不可变审计输入，不进入后台逐条处置。正常资讯采集、翻译、摘要、事件匹配、SiC 排名和边境榜单计算均自动完成，不进入日常人工审批队列。

本地开发可以使用开发专用密码适配器。生产后台使用独立 HTTPS 管理来源和项目内原生 WebAuthn/Passkey：唯一 `owner` 必须由设备完成用户验证，应用校验 RP ID、来源、挑战、签名和计数器后创建可撤销会话。生产不提供可由匿名公网直接尝试的共享密码登录，也不建设组织、邀请、通用 RBAC、审批流、全站富文本搭建器或复杂数据大屏。OPC 菜单是面向结构化服务目录的窄编辑器，不构成可改写资讯、来源、榜单或任意页面的通用 CMS。

采集、处理和来源健康诊断属于后台/本地运营能力。`/pipeline` 不进入公开导航，也不得向未认证公开用户展示服务器、跨区域拓扑、模型、阈值、源站错误或内部配置。

## 2. 权限边界

生产首发只配置一个 `owner` 身份 `lanzhouda@163.com`；所有写操作必须二次确认、记录操作日志并可识别管理员身份哈希和目标记录。保存草稿不要求重复登录，发布目录和确认、拒绝或撤回奖品等高风险操作必须在最近 5 分钟内完成 Passkey 再认证。后台不能：

- 手工修改事件证据、Star 快照、Star 基线或榜单分数；
- 绕过 OPC 发布校验发布服务；
- 将私密报名字段复制到公开内容；
- 把未通过结构化校验的模型输出直接发布；
- 用后台新增任意抓取 URL 绕过来源治理。

## 3. 登录与会话

- 管理页面和后台接口只接受配置的独立管理来源；公开站来源和 Node 端口不得进入后台。
- Passkey 必须绑定 `VAULT2077_ADMIN_ORIGIN` 派生的 RP ID，要求 resident credential 与用户验证。浏览器 ceremony 使用 `preferred` 兼容平台 PIN 与安全钥匙 PIN 的实际协商，服务端仍必须从签名 authenticator data 确认 `userVerified=true`；没有完成 PIN/生物识别不得注册、登录或再认证。挑战五分钟过期且只能消费一次，签名计数器并发冲突时拒绝请求。
- 本地开发密码至少 20 个字符并使用 Argon2id 哈希能力测试；开发密码适配器在 `NODE_ENV=production` 下关闭。
- 应用会话使用服务端随机不透明令牌，数据库只保存带密钥摘要。会话可单独撤销，空闲 30 分钟失效，绝对有效期 4 小时。
- 生产应用会话 Cookie 必须使用 `__Host-` 前缀、`HttpOnly`、`Secure`、`SameSite=Strict` 和根路径，不设置 `Domain`。Passkey ceremony 只在服务端持久化挑战及摘要，不使用跨站事务 Cookie。
- 浏览器写请求默认必须是 JSON；受保护的游骑兵头像上传是唯一 `multipart/form-data` 例外。两类请求都必须携带受控同源请求头，并通过 `Origin`/`Referer` 与 Fetch Metadata 检查。
- Passkey 证明无效、ceremony 重放、计数器冲突、会话创建/撤销、登录拒绝和恢复事件进入安全日志，但不保存完整邮箱、明文注册令牌、明文恢复码或完整 IP。

## 4. 后台导航

固定为：运行概览、OPC 菜单、边境计划、系统记录。后台不设置内容异常编辑器、来源组合编辑器或信息发布入口。

运行概览只读显示最近批次、失败任务、来源新鲜度、编辑积压、当前并发、熔断状态、主/备用健康、待发布 OPC 服务和待结算事项；正常指标不做装饰性图表。信息故障只能通过 workflow、worker 自动重试或代码修订处理，后台不提供暂停、切换、重放、改写或发布按钮。

只读诊断按 `vault_editorial` 与 `sic_editorial` 区分指标，但这两个名称不构成后台可操作资源。

首次上线期间，运行概览还必须只读显示 bootstrap 与 incremental 的区别、SiC 各 approved 来源的基线完成状态、Vault 基线窗口和失败来源。补跑使用 GitHub `workflow_dispatch` 或境内 worker 自动重试，不从后台触发。

## 5. 内容异常与纠错

公开用户可提交误合并、信息错误、来源失效三类问题报告。报告只写不可变审计记录并可作为自动重放或代码修正规则的输入；后台不展示逐条处置界面，也不能隐藏、恢复、移动、拆分、改写、重算或发布资讯、事件及 SiC 内容。自动重放不能形成完整合格结果时继续保留上一成功快照或原事件。

## 6. 来源组合治理

来源组合修订只通过版本库中的注册表、审查和部署流程生效，不在后台操作。参考项目或自有来源包中的具名条目只能自动进入候选注册表，不能因为上游项目获批就自动获得生产准入；每个生产入口必须明确归入机构新闻、路边社、SiC 内容组或平台榜之一。

同一原始内容只有一个主去向。结构信号可以先确定内容组或事件资格，境内 LLM 只做语义归类且不能推翻确定性禁入事件标记。Hacker News 与 Lobsters 已退出运行时；Follow Builders 的 X/Blogs/Podcasts 中央 feed 分别完整进入 roadside、SiC documents 和 SiC podcasts，不设本地上游来源审核；任一 feed 失败只告警并保留上一成功快照，不阻断 workflow。

后台只读查看来源组合版本、逻辑发布者和通道、最近成功及失败率。连续失败、恢复探测、主/备用切换和任务重试均由 worker 按固定规则自动执行；后台不得接受任意 URL、临时提示词或模型路由参数。

首批来源组合固定为 2026-07-22 信源审计报告所列七组项目的固定提交，经去重和在线核验后生成运行 bundle；后续增删或升级仍遵循本节治理方式。

## 7. OPC 菜单

后台支持基础设施、专项服务和游骑兵公开档案的新增、删除、排序、编辑、草稿、公开状态、修订、发布和停售，并维护游骑兵本人授权的公开联系渠道与公开头像。头像经服务端处理后进入 ADR-0016 的媒体存储，后台不接受任意第三方图片 URL；目录只保存对象引用，发布前复核引用对象。三个一级入口、三个基础设施浏览分组、六个专项专业领域和十个游骑兵身份仍由规格控制，运营人员不能把 OPC 编辑器扩展为任意栏目。

编辑与发布分离：保存草稿不会改变公开页面；发布使用当前草稿整体替换公开快照，必须二次确认并检查预期修订号。发生并发版本冲突时返回冲突并要求刷新，不能以后到请求静默覆盖。每次发布保留完整目录快照和不可变审计摘要。

正式发布前执行字段完整性检查；价格、范围、材料、周期、成果、修订、公开状态和游骑兵本人授权联系方式任一缺失或仍为预览占位值即阻止发布。

后台只记录专业负责人已确认的结果，不取代专业负责人作出法律、税务或其他专业判断。

### 7.1 OPC 订单与到账动作

新公开订单按 ADR-0020/0022 使用在线确认协议和线下对公转账。等待付款的银行订单只提供“确认银行到账”和“取消未付款订单”两个动作；到账确认要求最近五分钟再认证、预期订单版本和不可变审计，取消只适用于尚未确认到账且没有银行流水的订单。退役在线渠道记录只读，不显示查询、关单或原渠道退款动作。

银行到账核验必须使用站内结构化到账证据表单，不使用连续浏览器提示框。表单同时显示订单号、固定金额、收款户名和收款银行的不可编辑摘要，并采集银行流水号、付款户名和北京时间入账时间；管理员必须明确确认已逐项核对企业银行实际入账记录后才能提交。字段错误就地说明并聚焦首个错误，再认证过期或接口失败时保留已填写证据，不得执行部分写入。

后台不得输入任意目标状态，也不得把截图、回单图片、用户声明、客户退款申请或“已发起线下退款”直接登记为已到账或已退款。线下到账只由金额、付款户名、唯一流水号和入账时间核验推进；线下退款闭环尚未实现。公开退款申请在订单摘要中显示待联系标记，申请原因只在最近五分钟再认证的完整 dossier 中解密；客服使用原订单联系方式人工联系。居民身份证号码在 dossier 中只显示遮罩，联系信息导出不包含该字段。退役在线渠道记录只能用于历史核对，不得触发外部提供方操作。

每个订单使用一个贯通 dossier 展示服务和在线协议快照、付款资料修订、企业账户快照、签约主体、遮罩联系信息、对应渠道的交易证据、付款凭证、历史纸质合同结论、退款和审计摘要；这些数据来自同一订单读取接口，不由前端拼接多套状态。管理员可以预览和下载与用户相同的付款凭证图片。查看完整联系人、手机号和历史寄送地址是单独高风险动作，要求最近五分钟再认证并记录用途。

创建线下订单后，系统通过 outbox 异步向 `lanzhouda@163.com` 投递新订单提醒，包含订单号、服务、金额和指向 dossier 的独立管理域名链接；同时向用户必填的通知邮箱投递订单号、服务、金额、付款附言和公开订单状态入口。首次核验到账后，再分别向负责人和用户投递到账摘要。客户提交退款申请时，只向负责人写入一个 `refund_requested` 事件，包含脱敏订单摘要和 dossier 链接。所有邮件均不包含签约主体名称、退款原因、身份证号码、付款户名、完整手机号、地址、企业银行账号、订单恢复凭证、二维码或即时通讯账号；用户邮件不得包含后台链接。每个事件/受众复用独立稳定 Message-ID 并采用 at-least-once 语义；任一邮件失败不改变订单、到账或退款申请事实。

## 8. 边境计划

后台支持查看报名和当前赛季状态；奖品捐献只提供查看待确认记录、确认并加入随机奖池、拒绝和结算前撤回。

所有排名值、最终资格、季度冠军和随机分配结果只读。白天每两小时 Star 更新、季度结算、最终资格检查和随机奖品分配均由系统执行；后台不得修改 Star、基线、名次、指定奖品获得者或重复抽取。确认、拒绝或撤回奖品属于边境计划后台的写操作，必须明确目标奖品和结果。

## 9. 操作日志

每个写操作记录：时间、稳定管理员身份哈希、会话标识、动作、目标类型、目标 ID、结果、原因和不含敏感数据的差异摘要。日志不可通过普通后台界面修改或删除。

首发只有一个 `owner`，其身份来自固定 Passkey 主体而不是共享口令，因此审计可以把不同会话归到同一管理员。增加第二类人员权限时必须先修订本规格，不在环境变量中临时发明权限。

## 10. 失败与安全状态

- 数据库或存储不可用：后台只读并阻止写操作。
- 外部依赖失败：显示稳定错误码、最近成功时间和安全重试，不展示密钥或原始响应正文。
- 部分批次失败：保留上一公开版本，允许针对失败任务重试。
- 高风险操作冲突：以后到达的请求不得静默覆盖先前状态，返回冲突并要求刷新。
- 会话过期或被撤销：写操作返回未授权，前端保留未提交表单内容并要求重新进入安全身份入口。
- 高风险操作再认证过期：返回稳定错误码和再认证入口，不丢弃已保存草稿，也不执行目标操作。
- Passkey 存储不可用或没有有效凭证：不创建新会话；通过 SSH 本地命令签发十分钟一次性注册令牌，或用一枚离线恢复码兑换注册令牌，不提供公网找回密码。

## 11. 验收标准

- 未登录、错误管理来源、无有效 Passkey 身份或被撤销会话无法获得任何后台数据。
- 生产只接受固定 owner 的原生 Passkey；本地密码尝试受到限速和锁定，会话符合 Cookie 安全要求。
- 公开站域名和 Node 端口不能访问管理页面或后台接口。
- 会话可以单独撤销；高风险写操作在再认证超时后被拒绝。
- 正常内容发布、故障恢复和问题重放均由 workflow、worker 与编辑模型执行；后台不能处理或改写信息内容。
- 来源组合获批后，其明确来源自动进入候选注册表；只有完成用途、入口边界和单一主去向审核的来源进入生产。
- 任何公开数据修改、资格处置和服务发布都有操作日志。
- 后台无法直接写入排名数值或发布不完整的 OPC 服务。
- OPC 草稿、发布快照、版本冲突和增删改顺序通过同一服务目录接口验证；公开 OPC 路由只读取已发布快照。
- Passkey 私钥、完整管理员邮箱、会话摘要、私人邮箱、挑战哈希、恢复码哈希、LLM 密钥和原始敏感日志不出现在客户端响应；首次恢复码只显示一次。
- Vault 与 SiC 的队列、并发、熔断和故障切换相互隔离，自动切换可追溯且不会改变榜单或 Frontier 确定性数据。

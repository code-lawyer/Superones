# ADR-0015：当前快照、永久事件证据与自动编辑边界

## 决策

1. `information` 资讯瀑布是按原始发布时间计算的 30 天滚动公开窗口。一次 `bootstrap` 建立该窗口的真实基线；后续 `incremental` 只编辑并按稳定内容身份合并新增记录，成功空批次不得删除窗口内既有资讯，超过 30 天的资讯由境内持久化层自动淘汰。该窗口不是永久内容历史。`roadside`、SiC 内容组和平台榜只呈现各来源最近成功发布集合；只有明确完整的 `success` 来源集合可原子替换，`partial` 合并合格条目，`empty` 或 `failure` 均保留上一成功集合。
2. 来源失败或编辑未完成时保留该来源上一成功结果并标记更新延迟。来源被删除、暂停、退役或拒绝后，在对应注册表修订生效时从当前公开内容移除；事件簿证据不受影响。同一来源同轮分片的状态按整轮最差结果聚合，后到的成功分片不得掩盖先前失败。
3. 事件簿是唯一长期内容档案。事件永久保存稳定 ID、综合结论及形成事件时使用的不可变资讯证据副本；资讯离开 30 天滚动窗口或其他内容被新快照替换，不得导致事件证据 404 或丢失。
4. 已取得模型成功 completion 后，单条采集结果、翻译、摘要、SiC 内容或模型 JSON/Schema 的确定性校验失败先原地重试一次；批量模型正文仍无效时降级为逐条编辑，单条正文仍无效时只隔离该条，同批次其他合格记录继续发布。模型配置、DNS/TLS/HTTP、请求额度或无法取得成功 completion 的协议故障属于批次级基础设施失败，必须回滚并交给 inbox 重试，不能将批次误标为已处理。来源全部记录失败时不推进该来源成功快照。
5. 自动信息处理完全属于 workflow、境内 worker 和 `vault_editorial`/`sic_editorial`。运营后台不提供资讯、事件、SiC 内容或榜单的人工编辑、移动、隐藏、补写和发布入口；问题报告只用于审计和触发自动重放，不直接修改内容。
6. 编辑模型请求可配置每轮上限，生产基线为 Vault 300、SiC 200，也可设为 `unlimited`。达到上限必须进入 inbox 退避重试，不得丢失；始终强制有界并发、请求超时、主/备用路由、连续失败熔断和任务级指数退避，防止无限并发或故障风暴。
7. inbox 使用认领令牌防止过期 worker 迟到确认；瞬时失败最多六次指数退避。成功批次保留 30 天，隔离批次保留 180 天，随后由 worker 自动清理。
8. 采集 workflow 不重复执行全仓 lint、类型检查和测试。完整质量门禁在 pull request、推送到 `main` 及北京时间每日 06:30 独立执行。

## 生产节奏（北京时间）

| 任务 | 节奏 |
| --- | --- |
| information | 08:05–22:05，每两小时一次；采集重叠 24 小时，公开窗口滚动 30 天 |
| roadside | 08:55–22:55，每两小时一次 |
| SiC 论文、文档、课程、播客 | 每日 08:25 一次 |
| 平台原生榜 | 08:35、12:35、16:35、20:35 |
| Frontier 已验证仓库观察 | 08:45–22:45，每两小时一次 |
| 全仓质量检查 | 每日 06:30，并在 PR / `main` push 执行 |

00:00–08:00 不发起公开来源采集或 Frontier 常规观察。inbox worker 仍每五分钟运行，以便完成已接收任务、退避重试和清理。

## 结果

- 公开页面是可解释的当前状态，不是永久资讯数据库；information 只保留滚动 30 天，事件证据不依赖当前瀑布是否仍保留原条目。
- 发布采用幂等的“业务快照写入后确认 inbox”顺序。两步不是跨文档单事务，但 claim token、稳定批次 ID、单调快照时间和幂等写入保证安全重放。
- 失败来源、失败条目与正常条目分离；后台不再成为信息发布链路的人工瓶颈。

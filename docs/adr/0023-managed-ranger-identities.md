# ADR-0023：顾问身份随 OPC 目录受控发布

## 背景

ADR-0011 首版把十种顾问身份编译为静态分类法，避免后台成为任意栏目 CMS。真实运营需要增删、改名和排序顾问身份；继续使用中文名称作为顾问归属键，会让改名、删除、历史快照和跨模块读取产生无法稳定对齐的引用。

## 决定

顾问身份成为 OPC 服务目录中的结构化实体，使用不可随公开名称变化的稳定 ID，并与顾问档案保存在同一草稿、当前发布快照和历史发布快照中。每位游骑兵只引用一个 `identityId`；身份首次发布后锁定稳定 ID，受保护后台只编辑公开名称和顺序。空身份可以删除；仍被顾问引用的身份必须先在同一草稿中完成顾问迁移或移除，校验层拒绝任何孤立引用。

顾问身份继续通过 ADR-0011 的完整目录保存、乐观版本、发布前校验、最近再认证、原子发布和不可变审计通道管理，不建立独立分类 API、独立表或第二事实源。三个 OPC 一级入口、基础设施浏览分组和专项专业领域仍由规格与代码控制，后台不能创建 OPC 之外的任意栏目。

OPC 服务目录状态和 seed 升级为 schema v2。读取层必须按显式 `schemaVersion` 把 schema v1 的固定中文身份映射成稳定 ID，并同时转换草稿、当前发布目录和全部历史快照；schema v2 或后台请求缺少 `rangerIdentities` 时必须拒绝，不能静默恢复初始分类。下一次目录写入产生 v2。为保证当前和上一个 release 的应用回滚窗口，状态文档序列化器在 v2 顾问记录上派生一个非权威 legacy `identity` 影子值；当前代码、API 与业务校验只读取 `identityId`，影子值不建立第二事实源，并在不兼容的上一 release 退出回滚窗口后删除。生产继续使用 `vault2077_state_documents` 中同一个 `opc-service-catalog` JSONB 文档，不增加平行 SQL 字段。

## 后果

- 身份改名不改变顾问归属，身份排序决定公开左侧导航和空席顺序，真实顾问书脊仍遵循 `rangers[]` 的发布顺序。
- 删除只影响新发布快照；既有历史快照继续保存当时的身份定义和顾问归属。
- 初始十种身份只是 schema v1 的兼容基线，不再是永久冻结的产品分类法。
- 回滚到只识别固定中文身份的上一 release 时必须冻结 OPC 后台写入；自定义身份仅通过兼容影子映射维持公开目录可读，恢复新 release 后仍以 v2 `identityId` 和身份集合为准。
- ADR-0011 中“十个游骑兵身份只能修改规格和代码”的决定由本 ADR 取代，其余结构化目录边界继续有效。

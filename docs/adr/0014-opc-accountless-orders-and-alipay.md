# OPC 使用无账号签约订单与服务器端签署、到账核验

> 2026-08-05 修订：ADR-0019 已将当前公开纸质签约入口改为“在线协议确认并全额预付，人工合同结论后放行履约或全额退款”。本 ADR 的无账号订单、服务快照、支付宝服务器端核验、加密联系人和恢复凭证继续有效；以下“先电子签后付款”流程只保留为未来电子签约模式的历史与技术设计，不再作为当前纸质签约入口的门禁。

> 2026-08-12 修订：ADR-0022 已退役第三方在线支付的全部运行能力。本 ADR 中关于该提供方的实现只作为历史决策证据，不再构成当前系统能力或恢复授权。

OPC 标准服务允许公开用户在服务详情中直接登记订单。用户不创建 Vault2077 账号，不进入购物车，也不提交业务材料；订单保存下单时的服务编号、修订、公开价格、范围、周期和成果快照。签约方可以是自然人，或由法定代表人本人签署的法人/组织；首期不支持授权代理人、普通员工或企业内部审批链。

订单先进入 `awaiting_signature`。服务器按稳定控件协议从 e 签宝后台模板生成合同并创建签署流程，浏览器只跳转到 e 签宝托管的顶层 H5 签署页面，不在站内 iframe 收集证件、短信验证码、人脸或手写签名。异步通知只作为状态变化信号；服务器验签、按事件摘要幂等处理后仍须主动查询签署流程，确认流程与订单绑定、双方及签署区完成，下载最终 PDF、调用供应商验签并写入 ADR-0018 的专用私有归档，才将订单推进为 `awaiting_payment`。拒签、过期、撤销、验签/归档失败不得生成付款链接。合同正文可以在开发完成后由运营方上传，但模板必须使用项目约定的控件名称，并在上线前配置自然人/组织模板 ID、版本和生产凭证。

签署核验完成后，服务器使用支付宝官方 Node SDK 为唯一订单号、服务标题、固定金额和明确的收款商户 PID 生成 `alipay.trade.page.pay` 或 `alipay.trade.wap.pay` 收银台链接。用户在付款服务页面完成付款；支付宝异步通知通过 RSA2 验签，且 APPID、通知商户 PID、订单号、金额和交易状态全部一致后，系统自动更新订单状态。通知缺失时，受保护后台使用同一 APPID 和应用私钥签名调用 `alipay.trade.query`，并在写回前核对订单保存的商户 PID、订单号和金额。用户可见页面、条款、隐私说明、错误和操作文案统一使用中性签署与付款术语；底层适配器和受保护配置仍使用真实技术标识。

联系方式使用现有数据密钥环加密，只在受保护后台用于付款核验和服务联系。未付款取消订单满 90 天后清除非合同联系方式；已付款订单完成或退款满 24 个月后清除非合同联系方式及签署手机号。已签合同、合同当事人和验签/存证证据在专用私有归档保留 10 年。后台合同下载与联系方式导出分别要求最近五分钟再认证并审计。未签署/未归档订单收到真实成功付款时保存交易事实并进入 `payment_exception`，不得正常交付。生产配置缺少已上线应用、网站支付产品、商户 PID、应用私钥、支付宝公钥或私有合同归档时，前台下单入口必须保持不可用，部署门禁必须失败。浏览器返回页面、付款截图或用户声明不得改变签署或到账状态。

游骑兵协会不接入该订单或付款流程。用户仍直接联系外部独立顾问，Vault2077 不参与后续定价、付款、交付或争议。

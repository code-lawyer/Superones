# ADR-0010：生产持久化与安全状态统一进入 PostgreSQL

## 背景

内容、SiC、Frontier、平台榜和采集 inbox 原先各自维护文件与进程内写锁。该模式适合单机预览，但不能支持多副本、事务领取、分布式限速、不可变审计或可靠恢复。继续为每个业务模块分别加入数据库代码会扩大接口和迁移面。

## 决定

生产必须配置 `VAULT2077_DATABASE_URL` 并先运行版本化 SQL 迁移；缺少数据库时应用拒绝生产写入。`VAULT2077_ALLOW_FILE_PREVIEW=true` 只用于明确的本地/E2E 预览。

持久化分为两类：

- 内容、Frontier、平台榜、GitHub 条件缓存和公开回退任务通过统一 state-document 适配器保存业务聚合；PostgreSQL 使用行锁和事务更新一个聚合，文件实现只保留本地原子替换。SiC 按 ADR-0024 使用逐条规范化发布表，并在上一 release 回滚窗口内于同一事务兼容写旧状态文档。
- acquisition inbox、迁移记录、登录锁定、分布式限速和不可变审计使用专用关系表、唯一约束和适合其访问模式的索引；inbox 通过 `FOR UPDATE SKIP LOCKED` 支持多 worker 安全领取。

文件与 PostgreSQL 不做生产双写，也不在失败时互相静默回退。应用数据库角色不得拥有修改历史迁移的能力；审计表通过触发器拒绝 `UPDATE` 和 `DELETE`。

## 理由

业务聚合接口保持小而稳定，调用方不需要知道文件、JSONB、锁或事务细节；高并发、唯一性和安全状态则使用专用表，避免把通用文档存储误当队列。首版不提前拆出大量低价值关系表；当实际查询、容量或保留规则需要时，再通过新增迁移把特定聚合规范化。

## 后果

- Node.js 生产运行时最低为 24.7，以使用内置 Argon2id。
- 部署必须把 `npm run db:migrate` 作为启动前门禁并建立 PostgreSQL 备份/恢复。
- 数据库迁移和适配层已具备代码路径，但没有真实生产数据库、备份恢复和容量演练证据前，上线清单仍不得签字。
- Redis 继续保持可选；对象存储不因迁移 PostgreSQL 自动引入，仅 ADR-0016 定义的公开游骑兵头像例外进入 OSS。

# ADR-0021：OPC 退款申请与签约身份信息

## 决策

OPC 在全站页脚提供公开可发现的退款申请入口。用户输入订单号后，服务器仍必须验证该订单原恢复凭证；订单号本身不是读取或操作授权。恢复凭证可来自原下单浏览器的 HttpOnly Cookie 或 sessionStorage，错误订单号、错误凭证和不存在订单不得产生可用于枚举订单的差异化公开结果。安全查询只返回订单号、服务、固定金额、付款方式、业务状态和退款申请状态，不返回姓名、手机号、邮箱、居民身份证号码、银行账户、付款户名或交易流水。

只有已确认付款且尚未进入实际退款终态的订单可以新建退款申请。申请原因使用数据密钥环加密并与订单原子保存；同一订单重复提交返回现有申请，不创建第二份申请或第二个通知事件。申请事务写入一个只面向固定负责人的 `refund_requested` outbox 事件。邮件只包含订单号、服务、金额、当前业务状态和独立管理域名 dossier 链接，不包含申请原因或任何客户明文信息。

退款申请是客服与财务人工处理的入口，不是退款审批、银行付款或退款完成证据，不改变订单付款／履约状态。线下对公转账退款仍按 ADR-0020 的人工财务流程核验原付款账户、合同约定、服务进度、退款金额和银行结果；在独立退款状态机及银行证据实现前，任何公开或后台页面都不得把“申请已收到”表述为“已退款”。

新线下订单要求签约联系人的真实姓名、中国大陆手机号和有效 18 位居民身份证号码。客户端与服务端只做格式、出生日期和校验位验证，不宣称完成公安或第三方实名认证。居民身份证号码作为敏感个人信息和联系人一起字段加密，普通订单摘要、公开状态、付款凭证、联系信息导出、日志和邮件均不返回；最近五分钟 Passkey 再认证后的完整 dossier 也只显示遮罩值。

提交订单必须把服务协议确认与敏感个人信息单独同意拆成两个独立复选框，并保存同意版本和服务器确认时间。告知必须说明：身份证号码仅用于本订单签约主体核验及依法必要的合同留存，不用于营销、画像或与本订单无关的事项；姓名、手机号和邮箱还会用于订单履行、必要通知和退款联系。未付款取消满 90 天、已付款订单完成或退款满 24 个月后，身份证号码和退款申请原因随非必要联系人一起清除；依法必须留存的合同、财务、投诉或争议证据除外。

## 后果

- OPC 订单状态文档升级，但兼容没有身份证号码、单独同意或退款申请字段的历史订单。
- 退款申请理由只在最近再认证的后台 dossier 中解密；客服使用原订单联系方式联系用户，不由退款表单另收一套可被冒用的联系方式。
- 服务协议 PDF 和动态订单协议升级为 v2；生产替换必须按 ADR-0020 使用新付款资料修订原子发布，开放期间不得混用 v1 PDF 与 v2 动态协议。
- 生产开放前必须验证越权查询、重复申请、邮件脱敏、字段加密、清理策略、移动端和键盘操作。

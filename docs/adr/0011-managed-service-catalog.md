# ADR-0011：人工编辑只进入结构化服务目录

## 背景

Vault2077 的资讯、来源事实、SiC 内容与平台榜、Frontier 排名依赖自动采集和确定性处理，不应形成日常人工审批或手工改数流程。OPC 的基础设施、专项服务和游骑兵档案则是 Vault2077 主动向用户提供的业务内容，价格、范围、材料、周期、顾问联系信息、公开状态和修订会随经营变化，继续编译为静态常量会阻碍运营。

引入全站通用 CMS 会扩大权限、数据模型和发布风险，也会破坏自动内容不依赖人工管理的产品原则。

## 决定

建立一个结构化 OPC 服务目录模块，外部接口只提供：

- 读取最近一次已发布目录；
- 读取后台草稿及发布校验；
- 以预期修订号保存完整草稿；
- 通过完整性校验后发布完整快照。

后台可以增删、排序和编辑基础设施、专项服务及游骑兵具体记录；三个一级入口、三个基础设施浏览分组和六个专项专业领域仍由规格控制，不接受请求创建任意栏目。固定服务分类各自拥有随目录草稿、当前发布与历史快照保存的公开 `description`，后台只编辑说明，不改变受控分类集合、名称和顺序。首版十个游骑兵身份由规格固定的决定已被 ADR-0023 取代：顾问身份现在作为同一结构化 OPC 目录中的受控实体维护和发布。

保存草稿不影响前台。发布必须使用后台会话、二次确认、乐观并发检查、结构化校验和不可变审计，并保存完整历史快照。公开 OPC 页面在请求时只读取已发布快照，使新增稳定 slug 无需重新构建应用即可访问。

该接口不得接收或改写 Vault 资讯、来源注册表、SiC 内容/榜单、Frontier 参赛排名或采集器输入。

## 理由

这个 seam 把人工运营复杂度集中在一个深模块后面：前台只理解“已发布目录”，后台只理解“草稿与发布”，持久化、校验、冲突和历史由模块内部处理。它为真正需要人工维护的内容提供足够能力，同时避免建立全站 CMS、人工审批自动资讯或可手工修改榜单的危险接口。

## 后果

- OPC 公开目录与后台草稿进入 PostgreSQL 生产事实源；文件适配器只用于本地预览。
- 首版七项基础设施和十四项专项服务是初始化基线，不再是永久冻结的记录数量；具体项目变化必须通过受审计发布。
- 真实价格、周期、公开状态和游骑兵授权资料不完整时，后台允许保存草稿但拒绝发布。
- 如果未来出现 OPC 之外的人工服务目录，应先判断是否属于同一产品合同；不能仅为复用编辑器而把自动内容接入。

# ADR-0019：OPC 全额预付与纸质合同线上订单生命周期

## 决策

OPC 标准服务采用“在线确认订单及预付款协议、支付全款、线下完成纸质合同、线上放行履约或全额退款”的顺序。用户提交付款前必须能够完整阅读和下载在线订单及预付款协议，并主动确认服务快照、总价、收款主体、纸质合同样本、履约启动条件和全额退款规则。支付成功代表在线订单及预付款协议已经成立；纸质合同结果只控制是否放行服务，不得被描述为付款后所有合同关系是否成立的条件。

公开页面同时显示“电子签约”和“纸质签约”两个签约方式按钮。电子签约按钮使用原生 `disabled` 属性并以灰色不可操作状态呈现，纸质签约按钮可选择；按钮内外均不增加“筹备中”“当前可用”或同义状态文案。电子签约适配器、回调和归档代码可以保留，但不参与当前纸质签约入口的可用性判断、订单创建、支付门禁或生产部署门禁。

当前公开入口只创建 `signatureMethod=paper` 的订单。订单创建时保存不可变服务快照、人民币付款金额、在线协议完整正文/版本/SHA-256、用户确认时间、签约主体、加密联系人和加密寄送地址；服务器为唯一订单号生成支付宝企业商户动态收银台链接。浏览器返回、付款截图和用户声明不改变付款状态。异步通知必须通过 RSA2 验签并核对 APPID、商户 PID、订单号、金额和交易状态；主动查询必须由订单创建时绑定的 APPID 凭证发起、验证支付宝签名响应，并核对订单号、金额和状态，同时要求订单绑定的商户 PID 与当前受控配置一致。支付宝官方 `alipay.trade.query` 响应不返回卖家 PID，代码不得把本地 PID 冒充为响应字段。

支付宝电脑网站支付或手机网站支付的订单金额由服务器在创建动态收银台时固定，用户不能在付款页自行输入或修改金额。金额核对仍是强制门禁：它防止伪造/串单通知、错误订单映射、错误商户或环境配置、旧通知重放和代码缺陷把一笔真实交易写入错误订单。系统不使用需要用户输入金额的个人收款码或静态通用二维码。

线上订单状态固定为：

```text
awaiting_payment
  -> paid_pending_contract
  -> paid
  -> completed

awaiting_payment -> cancelled
paid_pending_contract|paid -> refund_pending -> refunded
任何无法安全归类的真实到账 -> payment_exception
```

`awaiting_payment -> cancelled` 不是普通后台状态写入。后台必须先主动查询支付宝；待付交易调用 `alipay.trade.close`，只有关单成功或支付宝已经返回 `TRADE_CLOSED` 才能写入本地取消。支付宝已付款时必须同步回写付款事实并拒绝取消；交易不存在且绝对付款期限尚未过去时也拒绝取消。支付链接同时写入支付宝绝对 `time_expire`，超过期限且交易仍不存在时，才可安全完成本地取消。该流程使用订单版本比较，避免取消检查期间又生成新付款链接。

`paid_pending_contract` 表示全款已经到账但尚未收到人工合同结论，系统不得启动或消耗服务；`paid` 表示受保护后台已经记录“纸质合同门禁通过”，可以进入履约；`refund_pending` 表示系统已经发起或必须发起全额原路退款，不能靠人工直接登记为 `refunded`。退款只有在支付宝退款接口或查询结果确认成功后才进入 `refunded`。打印费、寄出费和其他纸质签约成本由 Vault2077 承担，退款不得扣减。

线下寄送、签收、提醒、返寄和纸质文件核验由运营方自行执行，不进入本系统的流程设计。线上系统只在受保护后台提供两个业务结论：

- `approve_contract`：把 `paid_pending_contract` 推进为 `paid`；
- `refund_full_amount`：把 `paid_pending_contract` 或 `paid` 推进为 `refund_pending` 并调用支付宝全额退款。

这两个动作都要求最近五分钟管理员再认证、二次确认、预期版本和不可变审计。系统只保存结论、操作者、发生时间和必要的可选内部引用，不建立物流单、寄件任务、收件任务、催办日历或线下工作台。

支付宝服务器证据首次把订单推进为 `paid_pending_contract` 时，同一事务还必须生成不可变付款凭证快照并写入 `payment_confirmed` 通知 outbox。事务提交后，独立通知 worker 通过邮件适配器向固定生产管理员邮箱 `lanzhouda@163.com` 投递付款通知；邮件发送失败不得回滚到账事实或阻塞支付宝回调，而应按稳定事件 ID 重试、告警，并在所有重试中使用同一 RFC Message-ID。普通 SMTP 无法在“远端已接收、进程未落库”的崩溃窗口提供严格 exactly-once，系统采用 at-least-once 投递和稳定 Message-ID 抑制重复；若业务将来要求严格一次，必须换用支持幂等键的邮件供应商。邮件只包含订单号、服务、金额、付款时间、交易号和受保护后台链接，不包含签约主体名称、完整手机号、寄送地址或恢复凭证。

付款凭证不是发票。它必须列出凭证编号、订单号、服务编号/名称/范围快照、人民币实付金额、付款时间、支付宝交易号、我方名称、我方统一社会信用代码、用户签约主体资料、付款状态和生成时间；联系人手机号与寄送地址默认遮罩。凭证页显示不含秘密参数的规范网址 `https://superones.top`、当前页面规范路径和 ICP 备案号，并提供“下载付款凭证图片”。下载图片直接渲染同一不可变凭证快照，在图片正文中印出规范网址、备案号、凭证编号和校验摘要，文件名包含订单号；不得把带恢复令牌的实际地址、浏览器 Cookie 或后台地址写入图片。

## 模块与接口

订单生命周期由 `lib/opc-orders/` 这一个深模块承载；“一个模块”指共同的业务 interface、状态不变量和持久化 seam，不等于一个源文件。能力实现可以分为 checkout、signature、payment、refund 和 admin 文件，调用方只能使用这些业务 interface 或外部提供方编排 interface，不得引用内部存储、读取状态文档或直接赋值订单字段。公开路由、支付宝通知、付款返回页和后台不得各自复制普通状态判断。该模块的主要外部 interface 包括：

- `createCheckout`：验证公开服务和协议确认，创建待付款订单并返回支付会话；
- `readResumedOrder`：校验摘要式恢复凭证并返回当前公开状态；新的短期支付会话由恢复路由通过同一支付订单读取接口创建；
- `applyPaymentEvidence`：消费已验真的支付宝通知或查询结果并幂等推进状态；
- `approvePaperContract`、`beginFullRefund`、`confirmFullRefund`：记录后台纸质合同结论，并以明确的全额退款状态机处理支付宝结果；
- `completeOrder`：只允许已放行订单完成；
- `readPaymentReceipt`：通过有效订单恢复凭证读取同一不可变付款凭证；
- `readAdminOrderDossier`：为受保护后台聚合订单、签约主体、联系地址、协议、支付、凭证、合同结论、退款和审计摘要。

待付款取消是支付宝外部原子关单与本地状态写入的组合操作，由专用后台取消路由使用订单绑定的 APPID/PID 协调 `queryOpcAlipayTrade`、`closeOpcAlipayTrade` 和 `cancelAwaitingOpcOrderWithProviderEvidence`；后者明确区分 `provider_closed` 与 `expired_not_found`，审计保留真实依据。配置与订单绑定身份不一致时拒绝取消，通用状态更新接口也不得取消 `awaiting_payment`。

支付宝属于真实外部依赖，在模块内部使用生产适配器和测试适配器；文件预览存储与 PostgreSQL 是现有持久化 seam 的两个适配器。调用方只学习上述订单接口，不直接操作订单字段。

邮件也属于真实外部依赖：生产使用 TLS 邮件适配器，测试使用内存适配器。通知 outbox 与订单状态写入同一持久化事务，worker 只消费 outbox，不从支付宝回调路由直接同步发信。

## 隐私与保留

寄送地址只在用户选择纸质签约后收集，必须与联系人一同加密，只用于合同寄送、订单联系、退款和履约。隐私说明应披露处理目的、字段、受托处理、保存期限和用户权利。公开订单响应、日志、分析事件和支付宝商品标题不得包含地址、手机号、统一社会信用代码或内部备注。

未付款取消订单的地址和联系人最迟在取消满 90 天后清除；已付款订单在完成或退款满 24 个月后清除非合同联系和地址信息。在线订单及预付款协议快照、付款/退款凭证和审计记录按财税、争议与法定留存要求保存。纸质原件的线下保管不由本系统实现。

## 后果

- ADR-0014 的无账号订单、支付宝服务器端核验、加密联系人和恢复凭证继续有效；其中“先电子签后付款”和“未归档到账异常”的顺序被本 ADR 替换。
- ADR-0018 仅适用于未来重新启用电子签约的订单；其电子合同归档不得阻止纸质签约订单创建或支付。
- 当前生产开放纸质下单只依赖在线协议配置、支付宝生产配置、持久化、加密和退款能力，不依赖 e 签宝配置。
- 在支付宝全额退款接口、退款查询、失败重试和后台审计完成前，不得开放真实纸质签约付款入口。
